# Image codec preflight (not a published tool)

This implements the experiments in section 1 of OpenSpec change
`add-web-image-tools-and-categories`. Nothing here is an Astro route, and no
production page imports this directory. Candidates are exact development
dependencies in the independent website lockfile. Their installation is not
approval to distribute codecs in the public site.

From the repository root, with Node 24 and pnpm 10.33.0:

```sh
pnpm --dir website experiment:images:fixtures
pnpm --dir website experiment:images
```

Fixture generation requires macOS `/usr/bin/sips` and access to Apple ImageIO.
The second command builds with Astro's locked Vite, starts a loopback-only preview
at `http://127.0.0.1:4325/image-lab/`, runs installed Chrome through Playwright,
closes it and the server, then inventories the candidate distribution files.
`WEBSITE_BROWSER_CHANNEL` overrides the default `chrome` channel. It never
starts the public website, binds a LAN address, or deploys anything.

Outputs are ignored under `website/output/image-codecs/`: generated fixtures
and their manifest, isolated `dist/`, `results.json`, and
`dependency-inventory.json`. Do not copy this dist into `website/dist/` or
`website/public/`. Use a new manifest after regeneration: Apple ImageIO and
Sharp versions may change generated byte hashes.

## Corpus and checks

The 20 files are created exclusively from generated quadrant pixels. They
include JPEG/PNG/WebP; nonzero RGB under fully transparent alpha, plus partial
alpha; JPEG orientations 1/3/6/8; synthetic GPS/device/EXIF/XMP; truncated JPEG;
PNG with a JPEG extension; a real two-frame WebP; HEIC primary irot rotations 90/180/270 degrees, malformed/truncated HEIC and deliberately underreported ispe properties; and synthetic HEIC at
4032×3024 and 8064×6048. The HEIC files are original encoded HEIC bytes, never
picker-transcoded JPEG. **They are not iPhone camera originals** and cannot
establish iPhone/HDR/Live Photo/auxiliary-image behavior. No private directories,
photos, embedded location records, or user filenames are read.

The fixture tests check actual hashes/signatures/metadata, dimensions, animation
frame count, and the exact hidden RGB reference. The browser experiment checks:

- Real JPEG/WebP output with two quality values, signatures, and independent
  `createImageBitmap` decoding; PNG optimization with `optimiseAlpha: false`
  and decoded RGBA equality; store-mode ZIP creation and extraction with byte
  equality for the three encoded files.
- HEIC primary-image identification, primary dimensions **before application
  RGBA allocation**, full-size decode, and an explicitly exercised limit refusal.
  libheif parsing itself may allocate memory before the application guard.
- Actual HEIC worker termination after primary inspection, absence of delivered
  late results, and a deterministic CPU loop terminated by the timeout path.
  This is not a batch revision/state-machine test or proof of reclaimed memory.
- Lazy codec loading, same-origin resources beneath a non-root base, restrictive
  CSP without `unsafe-eval`, no COOP/COEP requirement, and browser console errors.

Each HEIC measurement starts a fresh worker. Run 2 may reuse HTTP caches but is
**not** a warmed persistent decoder. The RGBA allocation size is not peak memory;
no final resource policy or default quality is derived from these results.

## Candidate boundary

See [DEPENDENCIES.md](DEPENDENCIES.md) for fixed versions, license findings,
upstream source/build references and distribution findings. The baseline HEIC
experiment imports the package's **internal** CSP libheif binding via a
Vite alias. It is intentionally experimental and may change on package updates.
Unlike `heic-to`'s high-level adapter, it checks `is_primary()` and dimensions
before `new ImageData`. The library's CSP build is asm.js (`USE_WASM=0`), not a
HEIC WASM benchmark. The jSquash codecs use WASM.

The verified rebuilt candidate, source/license materials and independent
replacement proof are described in [REBUILD.md](REBUILD.md). Public integration
must carry the same materials and replaceable-library boundary. Production
queue/pages still wait for device and resource gates. Open tasks include real
camera originals, Safari HEIC orientation/color/alpha,
malformed-container behavior, Safari/iPhone runs, process peak memory and
reclamation, retained results/ZIP overhead, downloads/opening,
final limits, and the complete image workbench. Do not describe this preflight
as delivered image tools, full compatibility, device acceptance, or deployment.

## Device lab entry

[Mobile test steps](MOBILE-TEST.md) describe the bounded lab, exact preparation,
LAN server and sanitized feedback. `pnpm --dir website experiment:images:serve`
serves the verified `license-materials/browser-experiment/` snapshot, not a Vite
dev server or arbitrary repository files. Regenerate materials after changing
experiment sources. Only one operation runs; manual cancellation, pagehide and
clear terminate the worker. Optional JPEG quality 75 encoding and store-mode ZIP
retain one result, with explicit preview/download and URL cleanup. Raw file input
inspects actual bytes, never filenames/MIME, and never uploads. Experimental
32 MiB / 50 million pixel / 60 second values are not the production policy.

The original host's restrictive CSP/base and independent rebuilt-module
replacement are retested. The lab server checks indexed file integrity except
for the standalone libheif module, deliberately allowing LGPL library replacement
without a host hash veto. The manifest records the original verified bytes;
modified modules require their own behavior evidence. An underreported-ispe
fixture demonstrates both header readers can be wrong; the candidate fails
decode instead of producing output. Guards do not prove bounds on library
internal allocation. This failure is retained in the experiment evidence.

## Desktop process RSS experiment

After a passing rebuilt-module browser probe and refreshed license materials:

```sh
pnpm --dir website experiment:images:resources
```

The runner opens an isolated task-owned Chrome profile per scenario, samples
only its numeric process-tree RSS with macOS `ps`, and closes it. It covers
fresh-worker first/subsequent 12MP/48MP decode, active cancellation/recovery,
CPU-loop timeout/recovery, retained JPEG/ZIP/preview, clear plus a 5-second
observation, and bounded synthetic 16/64 MiB store-mode ZIP round trips.
It serves only the verified local bundle on 127.0.0.1:4328 and requires no external
network, personal files or desktop Safari setting changes. Chrome background
networking is disabled; this remains desktop Chrome evidence, not iPhone.

Results and all numeric samples are ignored under `output/image-codecs/resources/`.
Target sampling is 100 ms; short peaks can be missed. Summed RSS can double-count
shared mappings and is not physical footprint or proof of a leak. There is no
forced GC or guarantee that clear immediately returns RSS to the baseline.
The 3 GiB monitor ceiling is a test emergency stop, not production approval.
The archive-only diagnostic accepts at most four 16 MiB seeded synthetic
entries and does not appear as a mobile UI action. ZIP verification allocations
are included in observed RSS and its time is reported separately.

`process-memory.test.mjs` verifies tree isolation, KiB conversion, missing-root
handling and stale-worker removal. Do not infer production resource limits
from a single sampled run. Actual Safari/phone memory remains a separate gate.
