## Context

动机和产品范围见 [proposal.md](proposal.md)。需求已通过逐轮访谈确认；按本变更任务清单实施。

当前网站是独立 Astro 工程。`Page.astro` 组合双语目录和工具页面，`page.ts` 按工具懒加载交互模块；JSON/Base64 通过 `processor.ts`、`JobRunner` 和 `worker.ts` 执行纯 TS 规则。`contracts.ts` 已定义 1 MiB 输入、8 MiB 输出和带行列的类型化错误。`line-numbers.ts` 提供默认行号。网站主规范尚未同步，相关历史边界在 `usezero-web-tools-extension`、`extend-web-tools-batch-and-diff`、`add-web-markdown-editor` 和 `add-web-tools-feedback` 中；不修改这些变更的任务状态。

## Goals / Non-Goals

**Goals:**

- 把 Unicode 转换规则与 DOM、Worker、复制/下载解耦，支持确定性的领域测试。
- 在保留原始输入的前提下提供严格、单层、可解释的转换；位置始终对应原始输入。
- 复用现有基础设施，新增工具不增加其他页面的重型运行时依赖。

**Non-Goals:**

- 不生成完整的 JSON/Java/JS 字符串字面量；大写 `\uXXXX` 是输出表示，不能据此保证嵌入任意源文件后有效。尤其 Java 有编译前 Unicode 转义处理，实际控制字符和反斜杠需要额外的语言上下文。
- 不新增 Rust、桌面 IPC、远程计算、文件编码探测、编辑器语言包或自动 Unicode 归一化。

## Decisions

### 1. 专用纯规则模块，复用有界任务运行器

在 `website/src/lib/web-tools/` 增加 Unicode 规则模块，使用显式输入/选项类型和现有 `Result` 风格；在公共契约中增加 Unicode operation 和可本地化错误原因，避免 `any` 或用异常传递可预期错误。选项为类型化的 `escapeAscii: boolean`，不借用 MIME 等无关字段。

扩展已有 `execute.ts`/`worker.ts` 的 operation 分派和 `JobRunner` 接口；Unicode 的 DOM 生命周期放在独立的 `unicode.ts`，从 `page.ts` 按需初始化。沿用运行器的取消、5 秒时限和 requestId，同时由页面 revision 拒绝迟到结果。这样无需把新的示例、编码选项与 TXT 下载逻辑塞入包含图片/JSON 特例的 `processor.ts`。

替代方案：直接扩展整个 `processor.ts` 会增加对图片及 JSON 分支的耦合；复制一套 Worker/session 则重复取消和超时逻辑。实施前检查 `JobRunner` 的实际类型约束，采用小范围类型扩展，不重构其他工具。

### 2. 原始输入上的线性扫描与单层语义

固定形式识别小写 `u` 后恰好四个 ASCII 十六进制数字；字母数字的十六进制部分大小写均接受，第五个字符作为后续文本。花括号形式接受 1–6 个十六进制数字，码点不得超过 U+10FFFF 或落入 U+D800–U+DFFF。

连续原始反斜杠成对保留，只有奇数个中的末尾反斜杠可以启动 Unicode 转义。因此两个反斜杠加 `u4F60` 原样保留，三个反斜杠加 `u4F60` 变为两个反斜杠加“你”。其他转义和孤立的普通反斜杠原样保留；只有实际启动的 `\u` 序列进入严格语法验证。扫描仅前进，不重新扫描刚产生的字符。

固定形式的高代理项必须紧邻一个固定形式低代理项；孤立或逆序代理项报错。原始文本中的合法代理对原样保留，原始孤立代理项也报错，避免 UTF-8 编码时被静默替换。

位置记录原始 UTF-16 offset；错误行列从 1 开始，CRLF 算一次换行，CR/LF 各自也识别为换行，列按 UTF-16 单元计。报告首个错误，整次失败，无部分成功输出。

替代方案：`eval`/`Function` 会执行内容，不可采用；`JSON.parse` 和现有 `jsonc-parser` 适合 JSON 语法，却不符合混合文本、花括号码点及保留其他转义的契约；简单正则替换难以正确处理反斜杠奇偶、代理项及错误位置。使用标准字符串/码点 API 实现范围受限的扫描器，复用现有依赖而不引入全套语言解析器；实施前记录依赖适用性复核。

### 3. 唯一、可还原的编码表示

遍历有效 Unicode 文本，默认保留可打印 ASCII（U+0020–U+007E），但反斜杠 U+005C 始终输出 `\u005C`。U+0000–U+001F 和 U+007F 始终编码，实际换行为 `\u000A`；所有非 ASCII 字符编码为四位大写十六进制转义，补充平面字符输出固定形式的代理对。勾选“同时转义 ASCII”后，每个 ASCII 字符也编码。

这保证在两次输入均满足资源上限时，`decode(encode(text))` 与原始有效文本一致，包括字面量 `\u4F60`、反斜杠和控制字符。输入中的可见字符 `\n` 不等于实际换行；编码后再解码也必须保留这种区别。不 trim，不做 NFC/NFKC 或语言特定转义。

编码可能膨胀，8 MiB 下载结果不保证能再次通过 1 MiB 输入限制。界面说明该边界，禁止为方便往返静默截断。

### 4. 专用工作区，沿用共享文本体验

新增 `UnicodeWorkspace.astro`，复用现有布局、样式、`data-numbered` 文本框、共享状态/复制反馈。输入可编辑、结果只读；“Unicode 转文字”和“文字转 Unicode”为明确按钮。“同时转义 ASCII”默认未选中，说明仅影响编码；任何选项变更均使当前结果和待处理任务失效。

示例按钮只填充输入并使旧结果失效，不自动转换。复制使用现有失败回退。TXT 下载使用 `text/plain;charset=utf-8`、固定安全文件名及无 BOM 的完整 UTF-8 结果，不以 HTML 渲染。实际下载必须由点击触发；替换、清空、离页时撤销 Blob URL。成功的控制字符结果不得按视觉判空；空输入操作则显示明确的空输入提示。

任务开始、编辑、选项变化、错误、取消、超时均禁用旧复制/下载；任务失败保留输入和选项。离页清空源文本、结果与复制回退内容，终止 Worker；浏览器往返恢复沿用已有重置机制。宽屏并排，窄屏上下排列，保持键盘可达、可见焦点、实用触摸目标与双语状态。

### 5. 有界资源与本地处理

输入同时检查 UTF-16 长度快速上界和真实 UTF-8 字节数（1,048,576）；结果在构建过程中累计字节预算（8,388,608），超限立即失败，不先构建无界字符串。Worker 内重复必要校验，不依赖 UI 预检。使用有界片段拼接，避免退化的循环字符串拼接。

不写 URL、内容存储、遥测或反馈载荷；已有主题偏好不属于内容历史。5 秒任务时限与取消都终止 Worker，不能只隐藏繁忙状态。页面资产仍需网络，文案不承诺首次访问离线或零网络。

### 6. 发现入口与反馈保持现有边界

在 `web-tools.ts` 登记 `unicode` 为 development 类，双语短名称/描述/示例、`web-tool-guides.ts` 的步骤/FAQ/AI 使用说明和运行时文案同步更新。工具搜索使用既有名称/描述字段，将“Unicode 转文字”“Unicode 转义”等词纳入自然文案。动态路由、canonical/hreflang、sitemap、`llms.txt`/`llms-full.txt` 从同一目录生成；生产预计新增两个可索引页面，最终以生成结果为准。检查硬编码工具列表、图标映射、内容校验、测试、fixture、性能路由和相关双语说明。

新页面沿用 `Page.astro` 的反馈入口，在网站点击加载白名单及独立反馈工程的线程契约、双语主题标签中登记 `tools/unicode`；双语共享线程，默认关闭、点击才连接，只传线程/语言，不携带输入/结果。没有部署、数据库或管理员配置变更。此小范围契约修改仍需反馈工程自身验证。

## Risks / Trade-offs

- [“Unicode”可能被误解为所有编码] → 指南区分转义、码点、HTML 和 URL，并链接已有 URL 工具。
- [其他工具受共享契约和 Worker 修改影响] → 运行已有 JSON/Base64 与取消/超时回归，不修改它们的转换语义。
- [解码结果出现引号、换行或 HTML] → 输出保持纯文本；显式说明结果不保证是合法 JSON 或可直接嵌入的源码。
- [控制字符不易直接观察] → 示例同时展示字面转义与实际换行的区别，TXT/复制验证使用真实字符比较。
- [大结果使行号或文本框更新变慢] → 复用行号的现有限制，补充接近上限输入、展开编码输出及取消/超时实验，记录性能证据。
- [自动化被误当作设备支持] → Chrome 自动化、真实桌面 Safari 和真实 iPhone 的粘贴、emoji、复制、下载分别记录；缺失的手工验收保持待办。

## Migration Plan

没有用户数据迁移。先完成领域规则和测试，再接入 Worker/页面、发现入口和反馈线程，最后验证生成结果及设备流程。回退时移除新目录条目/页面接入和新增 operation；保留其他工具行为与所有用户数据。提交、部署、推送和归档均不包含在本规划步骤中。

## 实施选型核对（2026-10-30）

现有 `jsonc-parser@3.3.1` 用于严格 JSON，不适用于保留任意日志文本及其他转义的本工具。复用标准字符串/码点 API、现有类型化 Result、`JobRunner`、Worker、行号和复制反馈；未添加依赖或复制运行器。公共 ProcessorJob 仅增加 Unicode operation、明确的 ASCII 选项与类型化错误原因；其他工具语义保持原样。UTF-8 输出分段构建，单段约 8 KiB；UTF-16 源位置仅在首错时计算，避免逐次回扫。
