## Why

开发者从 JSON、日志和 Java 配置中复制出的 `\u4F60\u597D` 等转义文本不便阅读。Zero 当前的 JSON 解转义要求合法 JSON，Base64/URL 工具也不处理 Unicode 转义，因此需要一个能直接处理混合文本、规则明确的独立在线工具。

## What Changes

- 新增开发类工具“Unicode 转义转换 / Unicode escape converter”，提供 `/tools/unicode/` 和 `/en/tools/unicode/`，搜索说明涵盖“Unicode 转文字”。
- 双向转换：解码 `\uXXXX`、`\u{...}` 和合法 UTF-16 代理对；编码统一输出大写十六进制的 `\uXXXX`，补充平面字符输出两个转义单元。
- 普通文本与 Unicode 转义可混排；每次只处理一层，成对的原始反斜杠保留原样，不解析 JSON 结构、不解开其他转义、不递归解码。
- 默认编码非 ASCII 字符；反斜杠、ASCII 控制字符始终编码，以保持文字往返可还原；另提供“同时转义 ASCII”选项。
- 非法转义、无效码点和孤立代理项使整次操作失败，并显示原始输入的行列位置，不提供部分或陈旧结果。
- 复用文本工具的输入/结果区、默认行号、响应式布局、Worker 生命周期与状态反馈；提供两个方向按钮、示例、复制、TXT 下载、清空和取消。
- 输入上限 1 MiB UTF-8，结果上限 8 MiB UTF-8；只接受粘贴/键入的文本，不增加文件导入、内容历史或内容持久化。
- 补齐双语目录、搜索、静态指南、SEO/AI 索引及测试；沿用默认关闭的反馈入口，为新页面登记稳定线程，不启用服务。

不包含：`U+` 码点转换、HTML 实体、URL 编解码扩展、Unicode 字符查询/归一化、不可见字符检查、JSON 格式化、桌面插件和部署。

## Capabilities

### New Capabilities

- `web-unicode-tool`: 浏览器本地 Unicode 转义双向转换、严格错误、单层处理、可还原编码、有界交互及双语发现入口。

### Modified Capabilities

无。现有主规范仅覆盖桌面主窗口和 Awake 时长；网站相关能力仍位于其他未归档变更，本变更不修改或归档它们。

## Impact

- 主要修改独立 `website/` 工程：工具目录/指南/交互文案、工具页面组合、按需加载入口、纯 TS 转换规则、类型契约、Worker 调度、测试和发现输出。
- 复用 `JobRunner`、现有文本限额和行号等基础设施；保持 JSON、Base64/URL 既有语义。实施前复核现有依赖适用性，不预先引入通用编码器或大型编辑器。
- `feedback/shared/contracts.ts` 仅增加 `tools/unicode` 线程及相关验证，不改变部署、许可、审核或隐私边界；因此需要独立反馈工程检查。
- 实施时按实际生成结果更新工具数量及中英文项目说明；本提案不提前把第九个工具描述为已经交付。
- 无 Rust command、桌面 IPC、原生权限、发行清单或安装包变更。自动化、Safari/iPhone 实测与线上部署证据分开记录。
