## Correction

- `vendor/image-codecs/materials.zip` is an intentional versioned build input,
  accompanied by `bundle.json`. It contains the existing independently rebuilt
  decoder, ten exact upstream source archives, PNG/oxipng Rust source/vendor
  packages, notices, build recipes and independent replacement evidence.
- Normal preparation reads this ZIP directly, checks its pinned length and
  SHA-256 before decoding, bounds entry paths/count/expanded bytes, and applies
  the existing per-file, GPL/LGPL/IJG and replacement checks. Public assets are
  still replaced atomically, with current application source from the explicit
  allowlist. No network, native toolchain or ignored experiment cache is needed.
- `package:image-codecs` is an explicit maintainer update command. It verifies
  experimental materials and creates a reproducible ZIP with fixed timestamps
  and sorted entries. Browser experiment assets are excluded. Regeneration is
  separate from ordinary build; runtime compatible module replacement remains
  possible without a hash veto.
- CI explicitly prepares materials after locked dependency installation.
- The two synthetic HEIC fixtures and their original hash/provenance records
  are versioned in `tests/fixtures/image-codecs/`. Browser and performance
  checks use these test-only files; they are never copied to public assets.

Material ZIP: **52,868,051 bytes**, SHA-256
`a9655012367e0cf6b39fb5774f2226f807adcde4943d1b18c32bad7025c6f36c`.
Its size includes corresponding sources, not only the 3,340,062-byte decoder.
No new dependency or lockfile change was needed; the implementation reuses
the existing fixed `fflate` dependency.
