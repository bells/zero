## Context

动机与已确认范围见 [proposal.md](proposal.md)。当前 `website/` 是独立 Astro 静态项目，工具为 timestamp/json/base64/diff。`web-tools.ts` 是无分类的双语清单，`Page.astro` 提供平铺导航和目录，`page.ts` 提供工具区 Cmd/Ctrl+K 全工具搜索。没有独立的全站文档搜索，因此本变更保留既有全工具搜索语义，不扩展新的全站搜索产品。

当前 Base64 图片路径仅保留 PNG/JPEG/WebP 原始字节，限 5 MiB、1600 万像素；通用任务默认 5 秒。这些限制不能直接套用新的照片处理，也不能因新工具而放宽旧工具限制。计算契约在 `src/lib/web-tools/`，浏览器适配在 `src/scripts/web-tools/`。`feedback/shared/contracts.ts` 对五个既有线程做显式白名单。

本次只写规划文件。现有源码、官方候选库资料已做只读调研；尚未安装候选、运行图像编解码或测量 iPhone。主规范仍只有桌面能力，官网基础规范位于其他未归档变更内。

## Goals / Non-Goals

**Goals:**
- 通过共享类型和状态机复用三个图片工具，纯参数校验/几何/队列规则不依赖 DOM、Astro 或 Tauri；浏览器编解码保持可替换边界，方便后续评估桌面复用。
- 隔离大图、慢解码、取消与过期结果；使预览、下载、ZIP 和设置 revision 保持一致。
- 在静态说明、工具清单、发现产物、线程白名单和真实浏览器行为之间建立可验证契约。

**Non-Goals:**
- 不新增 Rust command、Tauri invoke 或桌面 UI；无跨端 IPC 变更。浏览器 Worker 使用显式 TS 判别联合契约，不引入 `any`。
- 不引入云端编解码、账户/历史记录、PWA 离线缓存、复杂图片编辑器或跨页任务持久化；不将移动视口测试当作 iPhone 实机证据。

## Decisions

### 1. 共享注册表驱动分类和双语入口

为工具注册表增加稳定 `category: 'development' | 'image'`，`all` 是筛选态，不是工具归属。四个既有工具归 development，三个新工具归 image。分类与工具展示都保留本地化名称；不为未来空分类预留可见标签。

目录增加内联搜索，在当前分类集合内匹配本地化标题、描述、slug/能力关键词；原全工具搜索对话框继续搜索全部七工具。空结果可一键改为全部并保留当前内存搜索词。切语言仅传递允许枚举的 `category` 查询参数；默认 all 可省略，未知值回落 all。分类参数不生成新 sitemap/index 项，canonical 指向无查询的目录；输入、搜索词和文件等仍禁止进入 URL。分类不写站点存储，唯一持久化例外仍是主题。

目录和所有普通链接预渲染。无 JS 时展示全部七项和分类信息，隐藏依赖脚本的筛选控件，保持说明和导航可用。新路由固定为 image-watermark、image-converter、image-compressor，保留原工具及桌面说明路由。增长后的工具导航按分类分组/紧凑呈现，避免增加三个全宽标签造成窄屏横向溢出。

替代方案：独立分类落地页会增加内容重复与索引维护；把分类加入 localStorage 会扩大既有隐私例外；只改全工具搜索又会失去分类内查找语义。因此采用目录筛选加既有全工具搜索的组合。

### 2. 三个入口、共享工作台和输出设置

三个工具页复用批量列表与结果卡片，每页只呈现当前任务需要的参数。转换和水印也提供输出格式、质量（仅 JPEG/WebP）和可选最长边。默认按输入保持 JPEG/PNG/WebP，HEIC/HEIF 默认 JPEG；转格式页允许显式统一目标。默认质量初值在样本评估后固定并显示，不暗示无损。最长边默认关闭，只缩小、不放大，按校正方向后的尺寸等比计算。

页面选择文件后只建立队列/做有界探测，明确点击处理后执行整批任务。预览使用有界缩略图，按需解码选中项，不在导入时解码整批。每项展示源/输出格式、方向校正后的尺寸、字节数、变化和状态。工具设置整批共享；改动设置使上一 revision 的结果不可下载，保留源文件供重新执行。不同工具页不转移文件；语言导航会清空文件状态，目录分类枚举可保留，并在活跃任务离页提示中说明清理行为。

替代方案：统一成多步流水线会增加状态和页面复杂度；完全重复三个实现会造成 HEIC/取消/下载契约分叉。采用共享工作台及适配器，不扩展跨页工作流。

### 3. 显式任务契约和单张顺序处理

拟新增纯 TS 图片契约、参数校验、几何、文件命名和队列规则；UI/Worker adapter 处理 File、Canvas、ImageBitmap、WASM 与 Blob。具体文件按职责拆分到现有 lib/scripts 目录，不将所有逻辑放进 `Page.astro` 或通用 `page.ts`。

任务状态为 queued → probing → decoding → transforming → encoding → success/failed/cancelled。请求包含 jobId、batchRevision、itemId、operation 和校验过的 settings；响应是 progress/result/error 判别联合，内部错误映射为稳定错误码（unsupported、invalid、limit、timeout、cancelled、decode、encode、resource、download 等）。文件名、像素、设置和错误原文不进入日志；未知消息必须收窄验证。

默认每批仅一张处于像素解码/编码中，专属 Worker 支持取消/超时 terminate；跨阶段 transfer buffer，尽量避免复制。预览绘制可使用主线程有界 Canvas，昂贵 codec 不同步阻塞 UI。终止后销毁 Worker，释放 ImageBitmap、Canvas、Blob URL 和临时缓冲；运行中的请求永远不能在 revision 变化、取消或清空后回写结果。

单张失败继续队列；重试失败项使用当前有效设置，其余同 revision 成功项保留。取消整批停止当前和未启动项，已完成且仍属于当前 revision 的结果可下载；取消项可由重新处理操作再次加入。清空则终止任务并撤销全部结果与预览。浏览器发生 OOM 之前只能尽量预防，不能承诺 terminate 一定救回已经崩溃的页面。

替代方案：Promise.all 并行全批会放大解码峰值；主线程 Canvas-only 会阻塞取消；直接复用通用五秒策略可能误拒正常 HEIC。采用串行 Worker 和独立图片资源策略。

### 4. 输入探测、HEIC 与像素语义

字节签名/容器与解码结果共同判定格式，不信任扩展名、MIME 或 file input accept。仅允许 JPEG、PNG、静态 WebP、HEIC/HEIF 的可解码主静态图；识别并拒绝 APNG/动画 WebP、多帧独立图像输入等不支持形式，不静默把动画当首帧。HEIC/HEIF 中辅助图/缩略图不等于支持导出多图容器；主图选择失败明确报错。

`image-meta@0.3.0` 已有 HEIC 容器尺寸探测，适合作为前置检查；它解析到的最大属性/裁剪属性不能作为唯一权威，还需在实际解码器取得主图 width/height 后、分配 RGBA 前复查像素和边长。检查整数溢出、极端长宽比、损坏容器、伪装类型和异常解码尺寸。

HEIC 优先评估 `heic-to`/libheif 的独立可终止 Worker 绑定，统一在 Chrome、桌面 Safari、iPhone Safari 使用经过验证的本地解码路径；不假定系统或浏览器天然支持。当前候选高层路径完整解码后再缩放，4800 万像素一份 RGBA 约 192 MB，输出缩小不能消除该峰值。12MP 和 48MP 使用不同边界样本实测；超过设备安全策略时在昂贵阶段前拒绝，不声称全部 iPhone 照片都支持。

处理顺序固定为识别/探测 → 解码及方向规范化一次 → 用户选择的等比缩小 → 水印（适用时）→ 必要的 JPEG 背景合成 → 编码/元数据清理 → 输出验证。避免浏览器已应用 EXIF 方向后再次旋转。水印几何以方向校正后、最终输出像素为基准，缩略预览仅缩放显示同一布局。普通静态输出不承诺保留 HDR/色域/Live Photo/深度等特性；方向、可见色彩和透明度仍必须纳入样本检查。

替代方案：仅原生浏览器解码无法覆盖所有 HEIC 场景；服务端兜底违反本地边界；首帧盲取可能产生错误主图。采用可验证的容器/主图解码路径，遇不支持明确失败。

### 5. 三种编码与 PNG 无损优化分路

优先评估 jSquash 的 MozJPEG、WebP、oxipng。JPEG/WebP 接受用户质量值；输出 MIME、实际字节签名和扩展名必须一致，不能因浏览器编码失败偷偷产出 PNG。Canvas 编码可作为经过矩阵验证的受控实现替代，不能改变产品行为；PNG 不使用 Canvas quality 假装质量压缩。

PNG 压缩且无缩放/水印时，保留正确方向的像素语义，去掉元数据，再使用 PNG 无损优化；必要的方向规范化需要重新生成像素。像素严格不变路径禁用会改变透明像素 RGB 的优化（如候选的 optimiseAlpha），测试包含透明像素。用户显式缩放/水印或转换格式属于明确变换，文案不把整个过程描述为原像素无损。

GPS、EXIF、XMP、设备等输入元数据不复制到任何新输出；PNG 原字节优化路径也必须清理相关块，而不能只假定重新编码完成了清理。支持解码所需颜色处理不等同于保留原拍摄元数据。原图保留是单独标注的原文件下载操作，不声称它已去元数据。

PNG/WebP 输出保留 alpha；选择 JPEG 时先提示无透明能力，默认白底且允许改色，再合成水印及图像正确的 alpha。收益按真实字节计算，等大/变大显示无收益；未实现固定体积自动搜索，不保证每次更小。

替代方案：对所有格式套质量滑杆会误导 PNG 用户；盲目转 JPEG 会破坏透明；只比较 Blob 大小不检查像素/格式可能把无效文件当成功。分路编码并验证输出。

### 6. 文字水印几何和预览

使用系统字体栈，文字为空/纯空白或超出公布字符上限时阻止水印处理；颜色、字号、透明度、旋转、边距和间距均有界且验证数值。单处模式九宫格锚点加边距，平铺模式使用有界网格覆盖输出画布；字号/边距/间距采用相对输出短边的统一规则，界面解释相对比例，混合尺寸批次得到一致视觉占比。控制参数有可理解的显示单位，避免将内部坐标暴露给用户。

使用同一布局计算产生预览和最终像素绘制；中英文、emoji、长文、多角度、超窄图片要检查测量和边界。预览可选一张代表图并逐张查看，不为每次滑杆变化重新生成所有原尺寸结果。改变水印设置只更新有界预览并使整批旧结果过期，实际批量输出仍由显式处理操作触发。

替代方案：自由拖动逐图排版或上传字体会扩大编辑器范围；缩略图单独套 CSS 水印会造成导出位置偏差。采用共享几何和系统字形。

### 7. 有界结果保留与 ZIP 下载

同时约束单文件字节、像素、边长、批量数量、合计源字节、单结果/合计结果字节、预览像素、每项处理时间和 ZIP 大小/耗时。具体安全数值由实施前实验固定为集中策略并展示，不沿用旧 Base64 限制，也不把“待定”带入上线页面。超限必须在可检测的最早阶段报错，保存已有有效结果；导航和取消保持响应。

优先评估维护中的流式 ZIP 库（如 fflate），固定实际版本/许可后选择。图片已压缩，ZIP 默认 store/低额外 CPU；打包只读当前 revision 成功结果。ZIP 前按总字节预检，打包中可取消，失败仍保留单张下载。不能因为顺序解码就忽略保存全部 Blob、打包复制和浏览器下载缓冲的内存；不把 File System Access API 作为 iPhone 必需能力。

命名使用源文件 basename 清理路径/控制字符后加操作后缀、实际格式扩展名，同批重名追加稳定序号；ZIP entry 不允许路径穿越。失败项不生成伪结果，打包前显示成功/失败数量；全部失败时禁用 ZIP。iPhone Safari 的 Blob 单张保存/ZIP 必须实机验证，不声称自动保存到相册。

### 8. 资源、许可和反馈隔离

HEIC/编码/ZIP 只在对应操作需要时从本站懒加载，其他工具和产品页不加载图片 codec；懒加载失败仅影响相关操作。首次入口仍遵守自动加载 executable JS gzip ≤50 KiB、首屏资源 ≤1 MiB，固定实验目标 performance/accessibility ≥95、LCP ≤2.5s、CLS ≤0.1；交互后的 codec 下载、首张/后续耗时、取消回收和内存单独记录。采用单线程 WASM Worker 起步，不为优化器多线程引入全站 COOP/COEP，避免影响反馈 iframe。

候选 [heic-to](https://github.com/hoppergee/heic-to) 调研时元数据版本 1.6.6，许可 LGPLv3-or-later；[jSquash](https://github.com/jamsinclair/jSquash) 顶层 Apache-2.0，实际 codec/传递依赖许可须按固定分发物复核。独立 chunk 不自动满足 LGPL；实施须保留通知/GPL/LGPL 文本，明确对应源码、修改、构建材料及替换/重建路径，核实最终浏览器分发机制的义务。许可或 WASM/CSP 构建验证未通过时，不宣称依赖已获准，不默默删掉 HEIC；记录阻塞并报告。当前候选来源已核查，不等于版本已锁定或法律结论。

反馈新增 tools/image-watermark、tools/image-converter、tools/image-compressor 三个固定线程，双语同线程；旧线程无迁移。仍只在点击后加载异源 iframe，仅传 thread/locale，禁用 referrer；照片、文件名、元数据、设置、搜索词、结果和草稿不通过 URL、postMessage 或日志泄露。反馈不可用不影响图片处理，当前默认关闭的配置和部署边界保持。

## Risks / Trade-offs

- [48MP HEIC 导致手机内存峰值] → 尺寸双重预检、单张 Worker、整体 Blob/ZIP 限制、实机测量并公开支持范围；不保证所有设备可处理。
- [iPhone 选择器自动转 JPEG 掩盖 HEIC 缺陷] → 电脑和可保留原格式的选图来源分别验证原始字节，记录来源/真实签名和 iOS/Safari 版本。
- [PNG 无损与元数据/方向规则互相干扰] → 分别校验可见方向、解码像素、清理后元数据和优化收益，不只看文件扩展名/体积。
- [浏览器字形和色彩差异] → 预览/导出同环境同布局，检查中英文字及 SDR/透明样本；不承诺跨系统像素完全相同或 HDR 保真。
- [静态预算被 codec 提前加载破坏] → 检查网络及构建图，对目录、既有工具、新图像页分别取证。
- [跨未归档规范的旧工具数量/上限冲突] → 本增量明确 scope；旧 Base64 规则继续有效，未来同步按依赖协调，不改历史勾选或主规范。

## Migration Plan

1. 已完成 codec、许可、12MP/48MP 与 Worker/CSP/base 的部分实验。按用户 2026-10-18 明确指示，继续分类与搜索 → 共享批量队列 → 转换/水印/压缩 → 双语说明及完整验收；使用集中、可执行的保守限额接入功能。Safari、原片、手机进程内存与最终资源策略保持发布前验收门禁，未完成不宣称实机/发布通过；不因暂缓而中断本地功能实现。
2. 增加静态路由、注册表分类、六个索引页面和三个反馈白名单项；旧 URL/线程不变。新增类型 enum 不从历史存储迁移用户文件。
3. 本地完成静态/浏览器/隐私验证，并单列桌面 Safari/iPhone Safari 证据。没有真实设备证据的任务保持未勾选，不能从 Chrome 仿真推定通过。
4. 提交、推送和部署均需独立授权。若未来需回滚，撤下新入口/路由和相应索引引用，保留旧工具；反馈线程数据不删除或重分配，必要时保留线程读取兼容。

## Open Questions

以下为可在既定契约内通过实验确定的实施参数，不是未决产品范围：codec/ZIP 精确版本与许可交付材料；质量初值和资源策略的具体数值；经实测可承受的设备/浏览器版本矩阵。必须在对应实施/验收任务完成前固定并记录，失败时报告限制，不扩大云端处理、静默缩图或 HEIC 输出范围。
