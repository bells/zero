## Context

动机见 `proposal.md`。当前官网为独立 Astro 静态站，`content/web-tools.ts` 注册三种工具，`components/webTools/Page.astro` 组合工作区，`scripts/web-tools/page.ts` 按工具加载控制器。`lib/web-tools/timestamp.ts` 已提供严格解析和六种时间表示；`contracts.ts`、`job-runner.ts` 与 `scripts/web-tools/worker.ts` 已处理 JSON/编码任务、5 秒超时、取消和 requestId 隔离。

现有 Job 的 input 只有 string/Uint8Array，输出主要是文本/图片，不能直接表达双输入差异或逐行批量状态。设计需要扩展显式契约，避免把复杂对象塞入字符串再反复解析。基础在线工具规范仍在 `usezero-web-tools-extension`；本轮创建新规划，不修改基础变更或既有 evidence。

参考依据为用户提供的 Diffchecker 截图及链接。2026-10-15 尝试打开参考网址超时，未核验其线上交互；仅借鉴截图中左右文本区、每侧打开文件、原始/更改后方向和查找差异操作，不将截图其他功能视为本次需求。

## Goals / Non-Goals

**Goals:**
- 保持纯 TS 逻辑、浏览器适配和 Astro 展示分离，复用现有错误反馈、主题、复制及任务生命周期。
- 批量与单条时间戳共用解析规则；差异结果可复现，并清楚标识行号、方向、换行差异与失败。
- 面向高差异率、长行、文件异步读取建立明确预算，基础输入始终可用，网站首屏预算保持现状。

**Non-Goals:**
- 本次不新增编辑器框架、实时逐键 diff、合并/冲突解决、补丁应用、文件树、历史/分享链接或二进制文档解析。
- 不在本轮加入 GBK/UTF-16 自动探测、自定义日期格式、其他时区/DST、CSV 批量导入或桌面插件；桌面复用仍为后续评估。

## Decisions

### 1. 复用站内入口，工作区按工具拆分

时间戳 URL 内以可访问模式按钮切换“单条/批量”，活动状态用 aria-pressed 表达；当前时钟保持独立，切换保留本页两个模式的源输入，但取消未完任务并使批量结果失效。批量单位和时区沿用现有选择项，默认 auto / UTC+08:00；不把输入或模式放进 URL/存储。

新增 slug `diff`，自动进入目录、搜索、工具导航及语言切换。将时间戳和对比工作区拆为小型 Astro 子组件，保留 Page 的公共状态/手动复制/说明区，避免继续扩大三工具条件分支。控制器建议 `timestamp-batch.ts`、`diff.ts`；计算建议 `timestamp-batch.ts`、`text-diff.ts`；文件读取是浏览器适配层，不依赖 Rust/IPC。具体命名可按现有结构收敛。

备选独立批量页面会增加重复 SEO 内容与入口；引入 React 或 Monaco 不能改善当前静态站隔离和预算，因此采用现有 Astro/原生控件。

### 2. 批量按物理行处理，共用单条语义

- 粘贴多行后显式“批量转换”，不跟随输入实时运行。支持 LF/CRLF/CR 分行；最后一个行终止符不制造额外空行。内部空白行跳过但保留其他结果的原始 1-based 行号，汇总成功/失败/跳过数量；全空输入返回提示。
- 一次最多 1,000 个物理行、总输入 1 MiB UTF-8；超过行数/总字节整批拒绝。每行沿用原始 256 字符上限，超长或非法行形成行错误，不阻断其他有效行。每条保存原文（包括外围空白），解析时沿用既有 trim 规则；不根据上一行猜单位。
- 每批采样一次 referenceNow，成功行包含原行号、原文、实际解释、秒、毫秒、北京时间、UTC、ISO 8601；相对时间不是批量列，避免时间流逝导致表格与导出变化。单条原有相对时间和暂停规则保持。
- 表格每页最多 100 行，行错误有本地化文本；完整结果不受分页影响。“复制 JSON / 下载 JSON”导出同一完整有序结构，包含 version、单位/时区、referenceNow、counts、rows；成功和失败使用显式联合类型，错误码及本地化说明均可导出。JSON 避免为首期增加 CSV 分隔、引号及电子表格公式执行契约。复制失败沿用手动选择回退；下载只在点击后创建固定名 `zero-timestamp-batch.json`。

备选遇错整批停止不利于日志排查；仅导出成功行会破坏原行对应关系，因此逐行保留失败。若以后需要 CSV/TSV，作为单独扩展定义可逆格式和安全语义。

### 3. 文本文件是输入来源，对比语义统一

两侧均有标签（原始/更改后）、可编辑 textarea、行号辅助、打开文件和文件名提示；支持一侧文件、一侧粘贴。输入行号辅助不重复进入屏幕阅读器阅读顺序。文件选择取消保持原内容；成功读取替换对应侧，随后编辑视为当前文本并移除文件名来源标识。读取失败保留原内容并清楚报错，不自动比较。

文件限制先检查 size 再读取，使用可中止的浏览器文件读取与严格 UTF-8 解码；可消费开头 UTF-8 BOM。拒绝无效 UTF-8、NUL、已识别常见二进制/容器签名（如 PDF、PNG、JPEG、ZIP/Office），不以扩展名/MIME 判断有效性，不声称能识别所有二进制。拒绝提示说明仅支持 UTF-8 文本，GBK/UTF-16 需先转换。粘贴文本同样拒绝 NUL。展示文件 basename，不读取/传播完整路径或将文件名用于下载名。

双侧异步读取各有 revision；输入编辑、再选文件、交换、清空、离页都会取消对应读取和当前比较，使旧结果失效。任一读取中禁止执行比较；读取从开始计时 5 秒超时并中止。备选 File.text() 默认替换非法字符，会把坏编码伪装成成功，因此不采用宽松解码。

### 4. 差异采用成熟算法，明确比较单位

候选采用 `diff`（jsdiff）的行级算法及字符级能力，实施前通过官方仓库/npm 核验近期维护、许可证、TS 类型、ESM/worker 兼容、Unicode 行为和打包体积；版本尚未选定，不将候选评估说成已通过。按需加载比较 worker，使该库不进入首页/目录/时间戳的初始依赖。若候选不满足硬契约，选兼容维护库并记录依据；不直接实现通用 Myers/LCS。

默认比较区分大小写与所有文本空白，仅将 CRLF/CR 行分隔规范为 LF；因此仅换行风格不同返回“内容相同（已统一换行符）”。保留终止换行的有无，不 trim 源文、排序 JSON 或做 Unicode NFC/NFD 归一化；终止换行差异用明确标记展示。空/空相同；空/非空为全新增或全删除。统计是新增行数、删除行数和连续差异块数；替换计为旧行删除 + 新行新增，不暗示存在唯一修改配对。

一个连续差异块内按顺序配对旧/新行进行行内比较，不承诺智能移动检测；字符片段按 Unicode 码点边界输出（不得拆断代理对），组合字符粒度另保留为已知限制。任一配对行超过 4,096 码点，或本次行内处理累计超过 100,000 码点，则对相应行显示整行变更，并提示“部分长文本仅显示行级差异”，行级结果仍完整。

首期不加忽略空白/大小写选项，避免比较影子文本与原文索引映射混淆；未来需要时再定义对齐与统计语义。

### 5. 差异视图可读、可导航且渲染有界

输入上方提供试用示例、交换、清空；主操作为“查找差异”，运行中可取消。结果与输入分区，桌面默认左右并排（各自原行号），可切换统一视图；≤720 CSS px 默认统一视图，用户仍可切换，切换不重算也不改输入。并排结果同步纵向滚动，水平溢出仅发生在文本容器。

增删除颜色外也有 +/−、明确标签及行号。统一视图使用两个来源行号，不把填充行伪装成真实行；相同、无结果、运行、失败状态有文案。前/后差异块按钮显示当前/总数，边界禁用，不循环；键盘操作将目标差异块滚动至可见并提供简短可访问状态，不逐行朗读整份文档。

默认每个差异块显示前后各 3 行上下文，长相同区折叠；分段/分页渲染使一次挂载的文本总量最多 200 KiB、结果行最多 400 行（两侧合计）。长行分段或按需展开，不能仅限制行数却一次挂载整份 MiB 文本。差异导航可跨页定位；折叠提示准确说明省略量，完整模型保留，不截断后声称已完整显示。安全渲染使用 textContent/文本节点及受控标记，用户内容不得作为 HTML。

截图只作为功能布局参考，使用现有字体、冷青品牌、浅深主题，不增加参考站广告/云保存侧栏。基本 textarea 足够支持输入，首期不增加 CodeMirror merge view；后者会扩大增强编辑、焦点与依赖范围。

### 6. 任务契约扩展为有类型的操作联合

保留 `Result<T>`、ToolError 与请求序号语义，将 Job/响应改为 operation 判别的显式联合：旧文本/图片任务保留现有字段，新 `timestamp-batch` 携带 source/unit/timezone/referenceNow，新 `text-diff` 携带 before/after；输出分别为 batch rows 和 diff hunks/segments/line numbers/counts。为 worker port/runner 提供泛型或专用类型适配，避免任意对象/any、JSON 字符串套壳和 UI 猜测结果类型；既有 JSON/Base64 页面必须回归。

预算：batch 总输入 1 MiB/1,000 行；diff 每侧 1 MiB UTF-8、20,000 行，合计最多 2 MiB；所有序列化结果（含错误、片段、元数据与 JSON 导出）最多 8 MiB。单行文本输入大小同样计入对应预算。worker 内在累积结果时检查上限，防止先创建巨型结果才拒绝；高差异率输入超过预算则报告限额并保留源文，不返回“截断成功”。

显式执行启动新 revision 并清除旧结果；输入/配置变化、切模式、交换、读取新文件、取消/清空/离页都使在途响应不可提交。worker 运行最多 5 秒，超时/取消终止 worker，重试新建；主线程保持编辑、导航、取消可用。批量输出的复制/导出只对最新成功批次开放；对比统计和导航只对最新成功比较开放。取消后的旧 FileReader/worker/动态 import 同样受 revision/isAlive 检查约束。

### 7. 隐私、发现与性能沿用官网基线

输入、文件名/内容、结果不进入网络/存储/URL/日志，只有主题 enum 可存。示例为静态合成内容；复制/下载必须显式操作，清空/离页释放 worker、文件引用、结果、手动复制值和导出 Blob URL，不承诺 JS 内存安全擦除。文件对比不使用上传接口，也不 fetch 内容中的 URL。

新增 diff 中英静态说明、输入语义/编码/限额/换行规则、示例、FAQ、WebApplication 实体；批量说明放在原时间戳页面。目录、搜索、AI 文本、sitemap 与 SEO 检查从注册表扩展为四种在线工具，全站索引页面 28，两个错误 HTML 仍 noindex。保持真实桌面 CTA、已有五工具文档、preview/production/base path/404；不改发行清单。

继承 initial executable JS gzip ≤50 KiB、首屏资源 ≤1 MiB，固定移动 Lighthouse performance/accessibility ≥95、LCP ≤2.5s、CLS ≤0.1。diff 库仅在主动比较后加载，动态 worker 路径适配 base。新增检查覆盖双语 diff 和时间戳两模式；性能脚本除首屏预算外记录批量上限、全异/长行 diff、算法加载和渲染压力下的取消/导航，不能用懒加载掩盖交互卡死。

## Risks / Trade-offs

- [UTF-8 限定无法直接读取某些旧日志] → 明示编码要求，不乱码成功，不增加不可靠自动探测。
- [diff 最坏复杂度与大量 DOM] → 双侧字节/行数/输出限制、5 秒可终止 worker、行内降级、按渲染字节和行数双重限额；记录本机实测，不承诺所有设备延迟。
- [顺序配对与码点高亮不等同语义/字素匹配] → 完整保留行级结果与原文，说明长行降级，不宣传智能合并或移动识别。
- [批量 JSON 导出不适合直接粘贴电子表格] → 首期保证结构与原行可追溯，按钮明确格式，CSV/TSV 后续另定。
- [扩展共享 runner 影响原工具] → 用操作联合与类型检查约束，回归原 JSON/编码的取消、超时和图片流程。
- [未同步基础规范中的“三工具”表述] → 新增能力明确四工具接入，保留前次历史文档；未来同步按依赖顺序统一主规范数量约束，不自动归档。

## Migration Plan

1. 按任务实施纯逻辑/契约和工作区，在网站独立依赖中锁定经核验的 diff 库，并同步许可文件。
2. 通过网站 check/test/build/test:seo/test:browser/verify:performance、strict OpenSpec 和 diff 检查，更新维护地图并记录实际证据和未验证边界。
3. 本变更没有持久化数据迁移；后续获得部署请求后发布整份静态站并核对新旧路由、worker/base/CSP 和索引响应。回退恢复上一网站产物及依赖锁文件。
4. 提交、推送、部署、搜索平台登记、spec sync 与归档继续按各自明确请求执行。
