## Context

动机与确认范围见 [proposal.md](proposal.md)。当前事实源为 `website/src/content/web-tools.ts`，九项归属为开发五项、图片三项、文本一项。`categories.ts` 定义分类枚举，`components/webTools/Page.astro` 组合页面，`scripts/web-tools/page.ts` 懒加载工具，`JobRunner` 已具备泛型输入／结果、超时和终止 Worker 的能力。

本设计衔接 `usezero-web-tools-extension` 的本地处理与页面外壳、`extend-web-tools-batch-and-diff` 的有界任务、`add-web-image-tools-and-categories` 的分类与图片策略、`add-web-markdown-editor` 的文本分类、`add-web-unicode-tool` 的九项目录和 `add-web-tools-feedback` 的异源反馈。相关旧文档保留带日期的历史数量。实施依据当前源码和本变更增量安排衔接。

## Goals / Non-Goals

### Goals

- 在现有 Astro 边界内交付八个独立、可重复使用的工作区，规则与 DOM、文件读取和下载分别组织。
- 为易产生歧义的日期、SQL、正则和 Cron 建立确定的行为契约。
- 复用成熟开源能力，单独计量按需计算资源及首屏资源。
- 使每项都可以通过领域、浏览器、发现输出和设备验收独立检查。

### Non-Goals

后续候选保留图片裁剪和 PDF 合并拆分。桌面插件、相机扫描、远程文件读取、云端计算、密码历史、数据库执行及定时任务调度属于其他产品范围。

### 2. 共同交互、隐私与资源预算

工作区统一具有输入／选项、明确执行按钮、状态、结果、复制、清空和适用的下载动作。示例填入数据后等待用户执行。任何影响计算的变更先使当前结果失效，再终止旧任务。错误、取消、超时保留输入和选项，旧下载与复制立即失效。晚到的文件读取、依赖加载和 Worker 回包均检查页面 revision。

文本结果完整值与 DOM 展示分开，普通结果允许复制和无 BOM UTF-8 TXT 下载。哈希下载为包含算法与摘要的 TXT，Cron 为包含基准时间和时区的 TXT，密码每行一条。日期结果为简短文本。复制失败采用现有手动复制回退。零长度的成功结果以成功状态识别。Blob URL、ImageBitmap、Canvas、Worker、文件引用、搜索框和复制回退在替换、清空及离页释放，历史恢复沿用现有重置方式。

| 项目 | 设计采用的首版限额 |
| --- | --- |
| 普通文本／SQL／正则样本文本 | 1 MiB UTF-8 输入，8 MiB 完整序列化结果，5 秒任务截止 |
| 文本整理 | 20,000 逻辑行 |
| 正则 | 表达式 8 KiB UTF-8，替换模板 64 KiB，最多 1,000 个匹配，每页 50 个 |
| 二维码生成 | 2,000 字节 UTF-8，纠错等级 M，1024 × 1024 PNG，生成的 SVG 路径矢量输出 |
| 二维码图片识别 | 单张静态 PNG/JPEG/WebP，16 MiB、12,200,000 像素、最长边 8192，10 秒端到端截止 |
| 二维码导出／解码文本 | 每项最多 4 MiB PNG/SVG，解码文本最多 64 KiB UTF-8 |
| 文件哈希 | 单个文件最多 256 MiB，按最多 1 MiB 分块读取，60 秒端到端截止 |
| 密码 | 长度 8–128，每批 1–100 条，总任务 5 秒，随机生成尝试次数最多 10,000 次 |
| 日期 | 公历 0001-01-01 至 9999-12-31，整数加减量绝对值最多 3,652,058 |
| Cron | 表达式 1 KiB UTF-8，未来 10 次，基准后 50 年内搜索，5 秒任务截止 |

所有单位与上限在指南和执行校验中同步表达。限制检查覆盖主线程预检、Worker 权威校验和结果构造，超限返回明确错误。执行耗时重任务用可终止 Worker，图片读取／解码也纳入端到端截止和迟到资源清理。

输入与结果保持在页面内存。普通首次资产、字体和计算依赖由本站加载，计算内容不进入 URL、站点存储、遥测、console 或反馈。新工具沿用内容默认不持久化的策略。首屏沿用 JS gzip 50 KiB、首屏资源 1 MiB 预算，主动执行后的库／WASM／解码资源单独记录。

### 3. 开源依赖与兼容性门槛

截至 2026-11-08 已核查以下官方项目的能力说明。它们是实施候选，准确版本、维护状态、许可证及传递依赖在任务 1 中记录并固定。

| 能力 | 优先候选与采用条件 |
| --- | --- |
| QR 编码／图片解码 | `qrcode` 与 `qr-scanner`，核验 Unicode 往返、SVG／PNG、静态图片接口、Worker 与 CSP/base-path 资源加载 |
| 增量哈希 | `hash-wasm`，四种摘要统一使用同一增量接口，核验 WASM 加载失败、分块正确性、体积与许可证 |
| SQL 格式化 | `sql-formatter`，只导入三种方言，核验真实解析／词法能力、注释与字面量保留 |
| Cron | 优先评估 `croner` 的分模式配置与日历能力，同时比对 `cron-parser`。通过本设计的 Unix／Spring 语义用例后采用 |
| 日期／密码／普通字符串规则 | 复用标准整数日历运算、`Intl`、Web Crypto 和标准字符串 API，作为范围明确的领域逻辑 |

源码核验发现 Croner 的默认日／星期组合和部分特殊日历语法、DST 行为具有独立约定，直接以六字段开关包装无法建立 Spring 兼容。适配层必须限定输入语法、显式指定日／星期组合、校验特殊日历表达式，并用 Spring 官方参考实现结果建立固定 fixtures。Unix 与 Spring 使用同一组结果模型，双语说明由已校验字段导出。

SQL 压缩先复核候选的公开词法接口和可复用 tokenizer。采用能识别选定方言的 token 边界的压缩路径，只折叠语法上可折叠的空白，保留注释、字面量和必要换行。若所选 formatter 缺少公开接口，在本工具适配范围内选择成熟 tokenizer，记录额外依赖。词法与真实数据库夹具必须通过后才交付压缩动作。

采用一个大型通用工具库会同时加载无关解析器。逐工具懒加载可控制首屏体积并保留清楚的依赖责任。对于 Cron 和 SQL，库候选未满足契约时继续处理对应依赖任务，工具完成状态以语义验收为准。

### 4. 二维码

默认文本模式可输入网址和任意有效 Unicode 文本，原文 UTF-8 编码，保留空格及换行。空输入报错，内容容量超限报错。固定 M 纠错和高对比黑白，PNG 使用完整模块和至少四模块静区，SVG 仅由库输出受控几何元素。识别模式接受单张已验证静态图片，识别首个可解二维码并说明单结果边界。解码结果使用纯文本展示，网址由用户复制，结果显示过程不请求目标地址。生成预览使用受控资源 URL。

QR 归属 image 只表示目录分类。`Page.astro` 当前按 image 分类显示既有图片 codec 许可链接，实施时将这类提示按真实依赖归属收敛，QR 页面给出自身依赖许可，防止分类扩展造成无关资源和格式承诺。

### 5. 文本整理

用户选择操作，固定执行顺序为逐行首尾空白清理、大小写转换、移除空行、去重、排序。默认只启用去重，大小写保持、排序关闭。清理采用明确列出的 ASCII 空格和制表符，空行判断为零长度或仅含这两类字符。去重区分大小写、保留第一次出现，作用于此前步骤的结果。排序按 UTF-16 单元的确定顺序升序／降序，保留相等项稳定顺序，指南提供数字字符串示例。

CRLF／CR 统一为 LF，末尾换行作为分隔符单独保存。输入 `a\n` 有一个内容行及终止换行，末尾分隔符本身不作为空白记录去重。结果有内容时保留原有终止换行，所有内容被移除时结果为空文本。采用标准非 locale 大小写转换，Unicode 扩展产生的输出也计入 8 MiB 限制。

### 6. 哈希与密码

哈希默认 SHA-256，每次选定一种算法和文本／文件模式。文本严格按当前有效 Unicode 原文 UTF-8 字节处理，空文本有效，空白和换行保留。文件按原始字节增量读取，零字节文件有效。输出小写十六进制，预期摘要允许两端空白和十六进制大小写，校验字符与算法长度后给出匹配／不匹配。算法、输入和文件切换使摘要失效。MD5／SHA-1 的碰撞限制在对应操作旁说明。

密码默认长度 20、数量 1，选中大写、小写和数字。可选符号字符集固定为 `!@#$%^&*()-_=+[]{}?`。每条必须包含每个选中组至少一个字符。以 `crypto.getRandomValues` 采样，通过拒绝采样消除取模偏差，再拒绝不满足字符组要求的整条候选，保证条件集合内的均匀分布。长度、数量、字符集和尝试次数均有界，安全随机源失败返回错误。页面不自动生成，结果仅在用户操作后出现。

### 7. 正则与 SQL

正则输入为模式正文，flags 提供 `g i m s u y`。匹配位置使用从零开始的 UTF-16 offset，并标注其含义。执行遵循 JavaScript RegExp 的全局、粘连、命名组和替换模板语义。零长度匹配按 Unicode 模式正确推进，避免死循环。编译错误、匹配数超限或替换结果超限使本次整体失败。匹配表分页展示，HTML 样本和替换结果采用惰性文本呈现。模式编译、匹配、替换均在独立 Worker 内执行。

SQL 默认 MySQL，显式切换 PostgreSQL／SQLite。格式化默认两空格缩进、保留标识符和关键字大小写，原样保留字符串与注释内容。压缩保留普通注释、MySQL 可执行注释及优化器提示，行注释的终止换行以及 PostgreSQL 相邻字符串所需换行都必须保留。所有输出保留原有 token 边界，碰到选定方言未支持的词法结构时返回错误。指南区分格式处理和数据库执行／有效性检查。

### 8. 日期与 Cron

日期按公历纯日期计算，严格接受 `YYYY-MM-DD`，使用日序整数建立日期差。自然日差为结束日减开始日，支持负数。同日为 0。排除周末的日期差先取较早日与较晚日，统计较早日之后至较晚日当天的周一至周五，再按原输入方向带符号。自然日加减按日序处理，排除周末加减从起始日之后／之前开始逐个符合日累计，0 保留起始日。周末仅指周六周日。计算与 DST、本机时区和法定调休数据解耦，界面同步显示计数规则。

Cron 默认 Unix 五字段，Spring 模式严格要求六字段。两种模式均支持字段范围、列表、步长、英文月份与星期名，星期 0／7 均表示周日。Unix 选用 Vixie 常用约定，月日与星期均受限时按 OR，通配及带通配步长的组合通过参考夹具固定。Spring 月日与星期按 AND，支持 `?`、`L`、`L-n`（n 为 1–27）、`LW`、`nW`、`dL`、`d#n` 等官方字段语义。模式解析必须先检查本模式的字段数、允许字段和特殊符号。

每次执行固定一个 UTC 基准瞬间，初始取当前时间，可输入带显式偏移的 ISO 时间以重现结果。IANA 时区默认浏览器识别值，失败时明确显示 UTC 回退。未来十次严格晚于基准、以 UTC 瞬间递增，同时显示目标时区本地时间和数值偏移。搜索在 50 年内找到不足十次时给出数量和搜索边界，无法找到也属于明确结果。任务超时属于计算错误，不等同于无未来执行时间。

DST 作为模式语义的一部分。Unix 预测器采用明确的固定时刻／间隔策略。分钟和小时均为单个数字时属于固定时刻，缺失时刻移到当天第一个有效瞬间，重复时刻只返回第一次。分钟或小时使用通配、列表、范围或步长时属于间隔表达式，缺失时刻跳过，重复时刻的两个 UTC 瞬间均返回。这个预测策略在指南中单独说明。以下 `America/New_York` 夹具构成其验收基线。

| Unix 表达式 | 基准 UTC | 基准后的前三次 UTC |
| --- | --- | --- |
| `30 2 * * *` | `2026-03-08T06:00:00Z` | `2026-03-08T07:00:00Z`、`2026-03-09T06:30:00Z`、`2026-03-10T06:30:00Z` |
| `30 1 * * *` | `2026-11-01T04:00:00Z` | `2026-11-01T05:30:00Z`、`2026-11-02T06:30:00Z`、`2026-11-03T06:30:00Z` |
| `*/30 * * * *` | `2026-03-08T06:45:00Z` | `2026-03-08T07:00:00Z`、`2026-03-08T07:30:00Z`、`2026-03-08T08:00:00Z` |
| `*/30 * * * *` | `2026-11-01T04:45:00Z` | `2026-11-01T05:00:00Z`、`2026-11-01T05:30:00Z`、`2026-11-01T06:00:00Z` |

Spring 以 `spring-context` 7.0.10 的 `CronExpression.next(ZonedDateTime)` 生成固定参考结果，夹具记录 JDK 及 tzdata 版本，覆盖上述两个切换方向和对应六字段表达式。规则说明按模式标明 DST 行为。适配库的默认行为只有通过相应模式的 fixtures 后才能使用。生成参考结果只用于开发验证，浏览器计算仍通过本地 TS 和按需开源依赖完成。

## Risks / Trade-offs

- [八项同时接入扩大回归面] → 按表中顺序逐项通过规则与工作区验证，再纳入共享目录和综合回归。
- [Cron 语法名称掩盖实现差异] → 使用显式模式、官方 Spring 参考 fixtures 和 DST／日历差异检查，保持兼容性任务可单独追踪。
- [SQL 空白压缩改变含义] → 采用方言词法路径，保留语义敏感换行、注释与字面量，对关键夹具执行数据库结果对照。
- [大文件哈希占用手机内存] → 分块、Worker、256 MiB 显式上限与端到端截止，记录峰值和清理效果。
- [分类触发无关图片 codec 加载或说明] → QR 按实际依赖选择初始化、许可提示和资源加载路径。
- [自动化结果扩大为设备或部署承诺] → 证据分别标注构建、浏览器自动化、真实设备和生产部署。

## Migration Plan

先核验依赖和语义夹具，再按表中顺序实现规则、工作区与按需任务。每项达到可用状态后登记双语目录和稳定反馈线程，最后更新当前地图及实际数量。发布前完成相关自动化与设备记录。回退按新增 slug 移除目录接入和专用资源，兼容已有分类查询值与旧页面入口。当前规划产物交由维护者审阅后进入实施。
