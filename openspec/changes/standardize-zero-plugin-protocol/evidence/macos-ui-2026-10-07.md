# Local macOS desktop UI verification — 2026-10-07

The same local Mac can validate Zero's native UI. The earlier inability to select the raw `pnpm tauri dev` process was an automation discovery issue; it does not justify treating macOS desktop validation as unavailable.

## Reproducible launch path

1. `pnpm tauri build --debug --bundles app` succeeded and produced `src-tauri/target/debug/bundle/macos/Zero.app`. Log: `build/plugin-verification/macos-app-build-20261007.log`.
2. Selecting that bundle by absolute path launched its process, but desktop automation timed out. A process check confirmed the bundle executable was running. The default configuration creates only a hidden tray window.
3. A local ignored configuration, `build/plugin-verification/macos-ui-smoke.config.json`, retains that tray and adds a visible `main` window titled `Zero — local UI smoke` (920×660). It reuses the already-built frontend and does not change the tracked Tauri config, identifier, capabilities, native handlers or public-runtime gate.
4. `pnpm tauri build --debug --bundles app --config build/plugin-verification/macos-ui-smoke.config.json` succeeded. Log: `build/plugin-verification/macos-visible-app-build-20261007.log`.
5. `cua.getApp("/Users/watson/work/zero/src-tauri/target/debug/bundle/macos/Zero.app")` then returned the real native window and its WKWebView accessibility tree. Subsequent verification used actual native clicks and settable UI controls, with fresh accessibility observations after each action.

The visible-window configuration is a test launch variant, not the normal tray-first startup policy. This debug bundle is not signed/notarized release acceptance. The normal hidden-window bundle and the raw dev executable remain separate launch cases.
