## Context

2026-10-12 搜索/AI 增量设计（用户已授权一并实施）：沿用独立 Astro 静态站与现有视觉。共享 Layout 负责搜索标题与实体图；文档内容集中在 typed content 模块，由一对双语 catch-all 静态路由生成五工具页、安装指南与 FAQ。首页保留视觉口号，但 title 明确产品类别；每个文档有唯一标题、description、稳定 section anchor、核对日期与来源。`llms.txt`/`llms-full.txt` 由同一内容与发行目录生成，不重复维护事实。已有 sitemap integration 自动加入文档与双语对应；排除错误页与文本索引。

实施顺序：先加入生成产物回归并确认旧输出失败，再实现 metadata/文档/文本索引/托管配置，之后构建并检查所有静态链接与实体，浏览器检查无 JS、双语路径和响应式/axe，最后记录性能和外部账号边界。Search Console/Bing 的账号验证与 sitemap 提交依赖实际可访问账号；部署、提交和推送仍单独授权。

## Goals / Non-Goals

**Goals:**

- 第一屏回答是什么、如何使用、从哪里获取；下一屏解释不同工具怎样完成具体任务。
- 以真实多表面交互构成独特记忆点，视觉质量依赖排版、留白、截图和细节。
- 页面主要内容静态输出；访客不启用 JavaScript 仍能阅读功能、切换语言并找到发布入口。
- 功能内容与发行数据独立建模，后续发布只需更新清单和相应素材，避免满页手改。
- 网站工具链、产物和依赖不进入 Tauri bundle 或 File 引擎，不影响桌面默认构建。

**Non-Goals:**

- 网站不调用 Tauri IPC、不转换上传文件、不连接本地应用、不模拟真实系统权限操作。
- 不引入 CMS、账户、订阅、在线插件安装或浏览器端 GitHub 轮询；不在第一版接入追踪、分析或广告。
- 不重画品牌图标、不改桌面视觉、不调整安装包策略、不借官网工作完成其他 change 的设备门禁。

## Decisions

### 1. 独立 Astro 静态站与最小依赖

新建 `website/`，拥有自己的 `package.json`、`pnpm-lock.yaml`、`tsconfig.json`、Astro 配置、源文件、资源与忽略的 `dist/`。沿用 pnpm 10.33.0/Node 24；根包仍为桌面项目，不为网站改成 workspace。使用 `pnpm --dir website ...` 和 CI `working-directory: website` 运行。独立入口避免根 `prebuild` 触发 File 引擎，也避免改写桌面锁文件。

选择依据：[Astro 官方 Islands 文档](https://docs.astro.build/en/concepts/islands/)支持静态 HTML 与按需交互。使用 Astro 原生组件和 CSS 完成布局，必要交互使用小型严格 TS 脚本；第一版不依赖 React hydration、状态库或 Motion。官网没有复杂应用状态，纯 CSS/原生元素可承担动效与展开，因此不会为通用能力自建复杂框架。

依赖采用官方 `astro`、`@astrojs/check`、`@astrojs/sitemap` 与项目兼容的 TypeScript；实施时核对维护状态、Node 兼容性并固定锁文件。验证使用维护中的 Playwright 与 axe 工具，图像使用 Astro 图像管线。品牌 SVG 直接复用；普通图标确有需要时复用 Lucide SVG 生态，不新增自绘通用图标库。

备选：根 Vite SPA 会耦合桌面启动/引擎和全页 JS；Next.js 的服务端能力超出本次需要；新独立仓库增加协作和版本同步成本。独立子项目在隔离与维护成本之间更适合第一版。

### 2. 清晰的单页产品叙事与小型安装页

路由：`/` 中文首页，`/en/` 英文首页，`/download/` 和 `/en/download/` 对应下载/试用说明，附本地化 404。锚点命名跨语言统一，语言切换保留等价路由与有效锚点，不强制按浏览器语言跳转。

| 顺序 | 内容与主要操作 |
| --- | --- |
| 导航 | Ø Zero、工具、使用方式、下载、GitHub、中/EN；小屏保持直接可达的原生折叠导航 |
| 首屏 | 拟定标题“随手调用，展开做事。”；副标题“截图、启动、防休眠与桌面壁纸，让常用工具各就其位。”；主入口随发行状态显示“下载 Zero”或“查看试用方式”，次入口“看看工具” |
| 产品主视觉 | 一行 Zero 工具入口与真实 main 工作区组成双层构图；同一工具在快速入口与完整工作区中的位置以细线/选中状态联系 |
| 使用方式 | “快速操作 / 完整工作区”两个场景，演示短操作和完整流程；静态状态都能读懂，不靠动画解释所有信息 |
| 工具 | 四个 standard 工具围绕任务展开；File 作为第五个产品方向单独标注“开发中，当前试用版未包含” |
| 平台与下载 | macOS/Windows 的实际包、架构和重要差异；详细选择进入下载页；不显示不可用的下载按钮 |
| FAQ 与页脚 | 安装权限、平台差异、File 状态、是否需要联网、更新方式；GitHub、安装说明、开发指南和版本记录 |

工具说明以动词开头：Snap“捕获、标注、复制”；Awake“让工作保持唤醒”；Paper“换一张桌面风景”；Launch“搜到，打开”；File“文档转换”（开发中）。Snap 的自定义编辑展示明确标注 macOS，Windows 为调用系统截图；不把平台差异藏到页脚。OCR 仅在存在相应公开包证据后进入该包的功能展示。

正文首层不展示 Rust、leases、policy 文件或内部构建变量；用户需要的条件与限制用普通语言。技术与协议信息通过开发指南链接按需访问。

备选：每工具一页会增加初版内容维护成本；大量等尺寸营销卡片难以展示操作关系。第一版选择首页场景叙事与下载页，工具深链用锚点即可。

### 3. 视觉方向：安静的桌面科技感

选定浅色内容画布、深色产品演示区的组合，而非另建双主题切换。大面积暖白 `#F7F7F2`、石墨正文 `#171A1F`、清晰灰色分隔线；少量冷青 `#087F8C` 仅用于当前工具、焦点和关键交互。深色演示区保留工具实际 UI 外观，不把所有截图统一染色。

- 构图：内容最大宽约 1200px，桌面首屏文案/工作区非对称分栏；底部工具入口带连接完整工作区。Ø 只使用现有 `zero.svg`/应用 master，不用字体字符冒充标记，也不任意变形。
- 排版：英文展示拟用 IBM Plex Sans，中文使用系统中文无衬线；少量版本/快捷键使用 IBM Plex Mono。字体按许可核对并本地提供 Latin WOFF2 子集，避免外部字体请求；正文优先可读性。标题使用响应式 `clamp`，不依赖强制换行保留版式。
- 工具区：交替的文字与界面局部展示，穿插一行精简工具索引；避免满页玻璃卡片、紫色光晕、球体、粒子背景、跑马灯和无依据指标。
- 动效：一次性 180–260ms 淡入/少量位移；鼠标或键盘选择工具时改变关联界面与选中提示。没有循环炫技、滚动劫持或必须等待的进场。`prefers-reduced-motion` 时立即切换。
- 真实素材：实施阶段通过合成安全数据采集截图，记录工具、平台、版本/profile 和捕获日期；保留清晰文字与有意义的 alt。网页交互仅展示已有截图，说明“界面展示”；不用 AI 生成界面当作功能证据。
- 移动端：首屏纵向排列；主视觉完整缩放或替换为窄幅截图；工具索引可换行，触摸目标不少于 44px。官网适配手机不表示 Zero 有移动端应用。

备选：全黑赛博风容易让功能图和长文本阅读失去层次；全白普通软件模板缺少辨识度。浅画布与深工作区的对照兼顾简洁与技术气质。

### 4. 类型化内容与可校验的发行目录

拟用 `website/src/content/` 保存本地双语产品内容与 `releases.json`；以 Astro 支持的 schema 校验和严格 TS 类型检查缺译、工具 ID、链接、状态和字段完整性。不得导入 React 插件、原生命令或 File 引擎；仅通过显式路径复制少量 canonical SVG，并记录来源/一致性检查。

产品工具记录包含工具 ID、本地化任务描述、平台差异、产品状态、截图来源与来源文档。发行记录包含：版本、发布日期、stable/trial 渠道、draft/published/unavailable 状态、core/standard profile、实际包含的工具 ID、平台、架构、安装格式、产物 URL、SHA-256、下载 bytes、签名/公证说明和核对日期/来源。安装后体积如有证据单列，绝不与压缩下载体积混合。

清单中的直接下载仅允许指向 Zero 仓库对应公开 Release 的 HTTPS asset，且核对版本、资产名和状态。构建/CI 不需要私人 token；不在客户端请求 GitHub API或“自动查最新”。常规本地构建离线验证 schema 和一致性，链接可达性/公开状态在联网验收和更新清单时核对，避免因暂时网络错误让页面宣称无法使用。

standard 是用户默认推荐，但仅当对应平台存在已核实公开产物；core 放在“其他配置”并注明无内置工具。未识别平台、Linux 或手机访客看到所有可用平台选择，不被强制下载；不通过 user agent 猜测 Apple Silicon/Intel。切换平台时移除前一平台选择的架构与产物，避免链接残留。

若只有 Draft/Actions artifacts：主页 CTA 为“查看试用方式”，下载页解释当前试用状态并链接仓库和试用说明；Actions artifact 必须提示需登录和可能过期，不能当稳定直链。File 不出现在 standard 下载清单。公开版本发布前只能使用此真实降级状态；官网内容完成不以公开 Release 就绪为前提。

备选：硬编码 latest/download 文件名容易跨版本断链；实时 GitHub API 受限流影响并引入客户端网络依赖；自动公布 Actions 草稿资产会误导安装。选择版本化清单和明确发布状态。

### 5. 可访问、SEO 和性能作为首版验收

- 语义导航/main/footer、跳过导航、唯一 H1、真实链接、选中状态的文本/ARIA、清晰 focus；FAQ 使用原生 `details`。所有关键内容无 JS 可用；交互增强失败时展示静态界面序列。
- 双语 title/description、正确 `lang`、canonical/hreflang、sitemap/robots 和来源可追踪的 Open Graph 图；SoftwareApplication 数据不含虚构评分、销量或未证实平台。生产域名配置与 base path 分离；临时预览 noindex，生产输出可索引。
- 首屏截图预加载且显式尺寸，非首屏 lazy；Astro 生成现代图像格式；静态内容不 hydration，不加载桌面依赖。无需请求第三方字体、分析或组件 CDN。
- 初版预算：每页初始 JS gzip ≤50 KiB，首屏所需静态传输（HTML/CSS/JS/首图/字体）≤1 MiB；预览执行固定协议的 Lighthouse mobile，目标 performance/accessibility ≥95，并记录环境。CLS ≤0.1、LCP 目标 ≤2.5s；这属于实验室目标，无法代表上线后的真实用户数据。
- 关键浏览器验收：1440px、768px、390px、320px，200% 缩放、长英文、键盘、无 JS、reduced motion、未知平台、无公开产物、资产断链。只验证官网，不从截图浏览推断桌面功能通过。

### 6. CI 与未来上线

新增独立网站检查工作流，仅安装 `website/` 锁定依赖并执行内容检查、类型检查、构建及必要的浏览器契约；只读取内容权限，不触发桌面 Release 或部署。根目录桌面测试/构建仍沿用原命令。

`docs/website.md` 记录本地开发、目录、清单更新、素材采集、检查和静态托管参数。默认输出可由常见静态服务托管；Vercel 可作为候选，但不创建项目、不绑定账号和域名。上线前再确认实际托管目标和部署授权，canonical 使用既有域名约定。

## Risks / Trade-offs

- [截图/功能与下载包不同步] → 每张图记录版本/platform/profile；清单约束已交付能力；审核 OCR、File 与公开插件措辞，未交付时明确标注。
- [下载仍处于试用阶段] → 用真实试用/发布说明保持可用入口，不生成虚构二进制地址，不让官网依赖发布才能落地。
- [内容双语增加维护负担] → 工具结构与发行数据共用，文案按相同键校验，英文缺译构建失败。
- [深浅混合或低对比破坏可读性] → 所有文字/控制按 WCAG AA 验收，冷色仅作局部强调；重点检查灰色说明和焦点。
- [重截图拖慢手机首屏] → 先定首屏素材与预算，保留尺寸并做现代格式/延迟加载，不加入背景视频。
- [独立锁文件需要两套依赖升级] → 网站升级在子目录处理并单独 CI；这是桌面隔离的可接受成本。
- [试用包未签名/公证影响安装] → 下载页给出准确安装条件和官方说明，不默认指导关闭系统防护，也不写“安装即用”保证。
- [内容本地处理措辞过度] → 区分本地任务与联网 Paper/更新下载；不声称“整个应用完全离线”或引用参考产品的隐私保证。

## Migration Plan

1. 实施网站隔离骨架和受校验内容；制作真实安全素材，完成双语首页/下载页。
2. 接入独立 CI 和文档，核对桌面默认构建不携带网站产物；生成本地可审阅预览。
3. 完成浏览器、内容/下载一致性与性能检查；保留当前未发布状态和各平台证据边界。
4. 用户另行授权上线时，核对托管参数、公开 release 清单与目标域名；预览通过后再切换生产部署。
5. 上线后发现问题可回退到上一静态产物/清单；官网不迁移应用用户数据，也不改变已发布安装包。

- 公开发行产物、签名状态和最终版本必须在清单更新时重新确认；初版允许没有公开产物。
