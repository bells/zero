## Why

Zero 已具备状态栏快速操作、独立工具工作区和五个工具的产品结构，但缺少能清楚解释产品、展示真实界面并引导安装的官网。建立一个简洁、务实、有辨识度的官网，让访客理解 Zero 如何融入日常桌面工作，同时准确区分源码能力与当前可下载版本。

## What Changes

- 新增独立静态产品站，拟位于仓库 `website/`，与 Tauri 桌面前端分开构建；沿用应用关于页已有的 `https://www.usezero.cn/` 作为目标 canonical 地址，实际部署另行授权。
- 用“随手调用，展开做事”表达产品定位：状态栏/托盘用于快速操作，主窗口承载完整工具流程，专用窗口服务具体任务。
- 建立以现有 Ø 图标、黑白层次、精确排版和少量冷色强调为基础的视觉系统；用真实界面、场景切换与克制动效体现创新和科技感。
- 提供中文默认首页和英文对应页面，包含产品演示、工具场景、平台差异、下载、常见问题与 GitHub/文档入口；移动端可浏览官网。
- 展示 Snap、Awake、Paper、Launch、File，并在功能附近说明平台和发行状态；明确当前 standard 试用版为四工具、core 为无内置工具、File 属于开发版且发行未就绪。
- 下载内容采用受校验的版本/配置/平台/架构清单；只有已公开、可访问的产物才能成为直接下载链接，无公开版本时提供可用的发布/试用说明入口。
- 补齐静态 SEO、社交分享、无脚本降级、键盘访问、减少动效与性能门禁，并提供独立构建和部署说明。

## Capabilities

### New Capabilities

- `product-website`: 官网产品表达、工具与多窗口展示、双语导航、响应式与可访问体验、静态构建和可发现性。
- `website-release-catalog`: 官网发行清单、平台/架构/配置选择、真实下载及未发布状态、能力与发行范围的一致性。

### Modified Capabilities

无。现有桌面行为、IPC、主规范和活跃变更的实现范围保持独立。

## Impact

- 预计新增 `website/` 源码、站点资源和独立锁文件、`.github/workflows/website-check.yml`、`docs/website.md`，以及 README 的官网开发入口；不改桌面 `src/`、Rust 服务、根依赖和打包链路。
- 技术方案采用 Astro 静态输出、严格 TypeScript、原生 CSS，以及经核对的官方/维护中组件与工具；优先复用现有 SVG 品牌资源，避免导入桌面应用和 File 引擎。
- 内容依赖 `package-zero-trial-profiles`、`standardize-zero-plugin-protocol`、`enhance-snap-and-share-offline-ocr` 等变更的最新证据，但不要求这些变更完成才能建设官网；未完成能力使用清晰状态说明。
- 不包含账号、支付、在线工具执行、插件商城服务、桌面功能扩展、遥测、正式版本发布、File 审批或公开第三方 runtime 开放；也不包含 DNS 修改、远端部署、推送或归档。
- 本轮只生成 proposal/design/specs/tasks；实施时分别验证网站构建、浏览器体验和既有桌面构建隔离，官网展示不构成设备或安装包验收。
