已有浏览器测试同时检查内容不外发和无异源请求。前者在反馈启用前后都必须成立；后者保留未点击路径，点击后仅容许明确反馈来源。计算代码仍不依赖第三方运行时。反馈必须和“工具输入本地计算”文案区分，不能使用户误以为主动提交的反馈也不上传。

## Goals / Non-Goals

**Goals:**
- 采用现成评论后端、审核与导出能力，通过薄适配层实现既定产品约束；不自行开发数据库评论平台或认证体系。
- 把静态计算页面、独立来源反馈应用、权威服务端审核划为三个边界，分别验证隐私、故障和资源预算。
- 固定线程/协议与公共数据契约，让语言切换、网站 base 和未来后端升级不改变反馈归属。

**Non-Goals:**
- 不增加游客账号、访客互相回复、附件、富文本、投票、自动翻译、邮件通知、订阅、需求看板、整站评论或桌面 IPC。
- 不默认开通收费、迁移主站到 SSR、接入分析/广告/第三方反垃圾 SDK，也不把免费套餐作为可用性保证。

## Decisions

### 1. Waline 为首选，但先验证固定版本的适配能力

2026-10-16 调研依据：Waline 官方[入门](https://waline.js.org/en/guide/get-started/)目前采用 Vercel + Neon；[客户端配置](https://waline.js.org/en/reference/client/props.html)支持可选资料/关闭登录；[服务端变量](https://waline.js.org/en/reference/server/env.html)提供 `COMMENT_AUDIT=true`；[服务端扩展点](https://waline.js.org/en/reference/server/config.html)和[后台导出源码](https://github.com/walinejs/waline/blob/main/packages/admin/src/pages/migration/index.jsx)支撑适配方向。调研读取文档及 main，不是已验证的发布版本。

实施先在本地锁定维护中的兼容发布版本、许可证与最小依赖，证明：匿名字段可选、全量审核、管理员身份验证、访客 API 隔离、纯文字原文保真、公开字段裁剪、导出/恢复都可以通过可维护扩展完成。失败时停止该候选，不通过暴露原生接口或放宽隐私/权限契约凑出可用版本；重新评估需记录差异。

2026-10-17 apply 决策：固定 `@waline/vercel@1.43.4`，按其发布 README/LICENSE 的 GPL v2 明确授权保守采用，保留 MIT 元数据冲突记录。独立 `feedback/` 适配服务按 GPL-2.0-only 提供，不改变网站/桌面许可。只导入发布包自带的官方 core（独立 core 未发布到 npm），不启动默认 ThinkJS HTTP/OAuth 服务；认证、审核和导出仍由 Waline core 承担。来源、边界与分发要求见 [许可核查](evidence/license-clarification-2026-10-17.md)。

不采用默认 Waline 客户端直接嵌入工具页：它的 Markdown、外部头像、图片/表情/GIF、回复与缓存行为超出本次范围。复用后端/后台，制作最小反馈前端与适配层，实际审计并关闭资料/草稿缓存和额外外部请求。Twikoo 的匿名字段与原生资料持久化需要更多适配；Giscus 要求 GitHub 登录；Cusdis 官方仓库已标明 deprecated，因此均非本次首选。

### 2. 静态主站和独立来源的反馈应用分开部署

本次新增 `feedback/` 独立工程，包含反馈前端、服务端适配、独立 lockfile 和部署说明；不得被网站常规构建或桌面打包隐式执行。站点配置只公开 HTTPS `feedbackOrigin`、启用标志和协议版本，不含数据库凭据或管理员令牌。相同来源、未知来源、缺失配置均视为未启用。

主站在工具操作区之后、现有说明/FAQ附近提供“反馈与建议”入口及简短数据说明。点击后展开独立来源 iframe，保留工具当前输入、worker、选区与滚动上下文。未点击不创建 iframe、预连接、预取或反馈请求；不预取评论数。反馈失败不使工具 disabled，也不触发工具重置。

iframe URL 仅含稳定线程编号与界面语言，不携带当前完整 URL、referrer、工具值或用户资料。设置 `referrerpolicy=no-referrer`、明确 title 和最小 sandbox（只允许脚本及反馈自身来源所需能力，禁止访问顶层导航、弹窗、下载和设备权限）。保留独立来源是使用 `allow-same-origin` 的前提，绝不回退到同源 iframe。访客不使用管理员 cookie；管理员在反馈站点顶层页面登录。

主站 CSP `frame-src` 只允许配置来源；反馈页 CSP `frame-ancestors` 只允许核准主站，反馈应用不加载外部头像、字体、分析或富内容资源。只接受结构化的 `ready`、`resize`、`error` 消息：`version: 1`，resize 为有限且有界的数值高度，error 为枚举；父页同时检查精确 `event.origin`、`event.source === iframe.contentWindow` 和字段 schema。未知消息丢弃，不执行任意 URL/HTML/存储操作；只控制反馈容器的本地状态与高度，不建立读取父页面的请求/响应接口。无权获取父页 DOM 是浏览器同源策略保证，点击加载本身不构成隔离。

### 3. 线程与用户可见交互

固定 allowlist 为 `tools`、`tools/timestamp`、`tools/json`、`tools/base64`、`tools/diff`。语言/base 不参与线程键，后端拒绝未知键或任意 URL 作为线程。目录说明面向整体问题、改进和新工具需求；子页显示当前工具，新增工具需求可链接回目录。

反馈区提供已审核的顶层列表和提交表单，原文显示且不自动翻译。顶层默认按提交时间倒序分页，每页至多 20 条；每条最多显示一层经认证站长回复，可分页获取回复，不一次拉全库。访客没有回复控件，服务端也拒绝伪造 parentId、管理员标记和状态字段。

表单仅含必填正文与可选昵称/邮箱，不增加分类必填项。正文为 trim 后 1–2000 个 Unicode code points，昵称最多 40 个、空值显示本地化“游客”；邮箱为空可提交，非空校验长度（最多 254 bytes）和合理语法，不证明邮箱所有权。请求体总量最多 16 KiB。数字等长度是首版实现约束，前后端必须一致，Unicode/换行语义需测试。

不将 Markdown/HTML转换为富内容，也不静默改写代码样例；存储边界保留纯文本语义，展示统一用文本节点及换行，URL 不生成远程预览或图片。提交示例 `<img>`、`![x](url)` 只显示原字符。纯文字反馈仍可能含个人信息，提交处说明审核后公开，提醒不粘贴密钥/私有文件内容。

成功仅表示服务端已持久化为待审核，不虚报“已发布”；不把待审核正文插入公共列表。失败保留本次 iframe 内存中的表单，关闭/离页释放，不写草稿到站点存储。提交超时结果不明时明确提示，不自动重发；同一提交尝试使用短期幂等键避免重复写入，服务器不向他人暴露该键或待审记录。

### 4. 公共契约和权威服务边界

所有 JSON 对象显式定义 TypeScript interface/union，用 `unknown` 验证网络和 message 输入，不使用 `any`。无 Rust 或 Tauri IPC 变化。

| 契约 | 字段与边界 |
| --- | --- |
| CreateFeedbackRequest | threadId、content、可选 nickname/email；idempotencyKey 为本次尝试随机值，不是身份凭证；拒绝额外权限/审核/父级字段 |
| CreateFeedbackResult | receiptId、status=awaiting_moderation；不得返回联系信息、审核令牌或公开发布成功 |
| PublicFeedback | id、threadId、content、displayName、createdAt、authorRole=visitor/owner；回复另带已批准的 parentId；无 email、邮箱哈希、IP、UA、私有审核字段 |
| FeedbackPage | items、nextCursor；cursor 有界/校验，不允许任意数据库查询，私有字段不进入错误或游标 |
| FeedbackError | 本地化映射用 code（invalid_input/rate_limited/unavailable/timeout 等）及安全 retryAfterSeconds；不回传服务堆栈、SQL、凭据或请求正文 |

新增访客 facade 只开放公开列表/回复查询和创建顶层待审反馈。Waline 数据/审核/管理员接口不得成为绕过 facade 的第二条访客通路：原生评论读写、注册、导出、用户信息等入口必须禁用或由服务端认证/适配层保护；路由级验证是候选可行性门禁的一部分。只设置客户端参数或 CORS 不等于权限控制。

管理员复用经验证的 Waline 服务端身份与权限，不靠昵称、邮箱或客户端 role 判断站长。首次管理员建立在限制访问的初始化阶段完成，公共启用前关闭游客注册/管理员抢注入口。管理员写入、审核、删除、导出须认证，并验证 Origin/CSRF 和会话权限；已认证站长回复可直接发布，视为站长完成审核。回复只挂在同线程已公开顶层反馈下，删除/隐藏父反馈时所有公开读取也隐藏其回复。

公开查询始终在服务端筛掉待审/拒绝/删除内容并使用白名单 DTO；分页/计数/直接 ID 查询同样不能泄漏。联系方式只在授权后台可见，不计算外部头像哈希、不传 Akismet 等服务、不配置 SMTP。邮箱不验证所有权，后续人工联系需站长自行判断；本次不实现自动通知。

### 5. 防滥用与数据生命周期

先实施有界 payload、分页、待审默认值、幂等处理、空白/重复内容校验和服务端限流；首版默认同一来源标识每 10 分钟最多 5 次提交，拒绝返回 429 与重试说明。来源标识从受信任平台转发信息派生短期加盐摘要，只用于限流，明确过期（不超过 24 小时）；不信任客户端任意 X-Forwarded-For。计数跨函数实例有效，不使用仅进程内 Map 冒充分布式限流。

不增加第三方验证码/反垃圾请求作为隐含依赖。Origin allowlist 仅是浏览器边界，不能阻止脚本模拟；审核加速率限制仍可能被批量绕过，因此需要全局写入上限/关闭写入口的开关及配额告警/人工巡检。部署前依据实际免费额度确定上限，达到上限明确暂停反馈，不升级付费或影响工具计算。

应用不主动持久化原始 IP/UA、工具输入或完整 referrer；平台网络日志可能包含连接元数据，公开说明不承诺网络匿名。禁用正文/邮箱/请求体日志；管理员备份视为私有资料，不能提交仓库或公开站点。后台支持删除反馈及联系方式；保留期限、平台日志与备份保留策略在启用前形成清晰的隐私/维护说明，不虚构已有自动过期机制。

### 6. 开关、免费资格与证据分层

主站未配置或验证不通过时不加载任何反馈来源，只显示未启用说明和既有 GitHub Issues 备用链接，不展示可成功提交的假表单。失败提示不声称 GitHub 是免登录替代。主站预览默认不连接生产服务/生产库；本地和预览使用合成数据、独立测试库及明确允许的父来源。

当前 [Vercel Hobby](https://vercel.com/docs/plans/hobby) 限定个人非商业用途，[Neon Free](https://neon.com/pricing) 的实际额度需创建时核实。无需把经常变化的免费额度数字写入产品承诺。启用记录必须包含站点用途/套餐资格、预计开销、硬上限/超额行为、是否需绑卡、区域和供应商元数据边界；不自动升级套餐。满足零新增费用且不需自行运维常驻服务器才继续该首选方案，否则保持禁用并重新选型。

主站原有初始 JS gzip ≤50 KiB、首屏资源 ≤1 MiB 和 Lighthouse mobile performance/accessibility ≥95、LCP ≤2.5s、CLS ≤0.1 保留，含自动加载的入口代码；反馈负载只在点击后发生，单独记录大小/延迟/错误/内存及布局行为，不通过忽略自动请求规避预算。UI 覆盖中英、浅深/system、键盘、44px 触摸目标、320px、200% 缩放及 reduced motion；跨来源 iframe 内外都验收。

## Risks / Trade-offs

- [成熟评论系统默认行为大于需求] → 先做固定版本的路由/原文/权限验证；必要的 facade 保持小而明确，不 fork 整个平台，不用 UI 隐藏代替服务端约束。
- [匿名广告消耗人工和免费配额] → 审核、持久限流、全局开关/写入上限并用；不承诺即时审核或必然采纳建议。
- [免费服务冷启动、暂停或套餐不适用] → 记录实测与账户资格，失败仅影响反馈；不将本地测试或文档额度当作线上 SLA。
- [跨站 cookie/存储限制导致嵌入失败] → 访客不依赖 cookie 或持久存储，管理员顶层登录；实际 Chrome/Safari 场景单独验证。
- [公开回复泄漏私密字段或被原生 API 绕过] → 全路由负向测试、服务端白名单和管理认证；上线前未证实即保持禁用。
- [升级丢失扩展约束、导出含私密资料] → 锁版本、升级回归、私有备份和合成恢复演练，真实生产导出不放仓库。

## Migration Plan

1. 提案后经 apply 实施本地候选验证和服务，主站开关默认关闭。无需迁移既有工具/桌面数据。
2. 经单独授权配置云资源/域名/秘密，初始化管理员及测试库，核实免费资格与保留策略；所有秘密只在服务端环境中注入。
3. 预览使用隔离数据验证真实 iframe/CSP、匿名提交/待审/审核/回复/导出恢复；记录自动、托管和人工证据，不标记未运行项完成。
4. 经部署授权后发布服务，核查公开接口与管理员隔离；最后启用生产主站入口，验证共享线程和工具隐私不变。
5. 回滚先关闭主站入口与服务端访客写入；保留私有备份、可审核数据及管理入口，不删除数据库。升级先导出并验证迁移可逆性；不能安全恢复则保持反馈关闭。
