## Context

动机与确认范围见 [proposal.md](proposal.md)。当前定位入口为 `captureToolbarModel.ts`，`CaptureApp.tsx` 通过 ResizeObserver 测量包含实际属性面板的 stack；优先级为外下、内下、外上，横向右对齐。`useCapturePropertyAnchor.ts` 维护按钮关联，但属性面板依赖正常流固定向下。

`captureGeometryModel.ts` 定位尺寸/圆角条；现有 toolbar obstacle pass 可能为避让它而覆盖主定位顺序。默认值由 `captureAnnotationProperties.ts` 定义，通过 `useCaptureToolDefaults.ts` 与 `captureToolDefaults.ts` 存储在 `zero.snap.annotation-defaults.v1`。有效旧绿色无法与用户主动选择的绿色区分，因此保留所有有效保存颜色。

相关规则尚未进入主 specs：本变更以两个独立 capability 描述收敛后的行为，不改写前置变更的历史证据。未来同步/归档需要协调前置 `screenshot-toolbar`、`snap-annotation-properties`、`snap-annotation-tool-defaults` 与本变更，消除旧定位/朝向/绿色工厂默认条款的冲突；不是简单追加并留下两套互斥规则。

## Goals / Non-Goals

**Goals:**

- 将自动定位、空间测量、工具栏整组拖动、样式默认值分成可独立验证的职责，保持主工具栏稳定。
- 所有屏幕坐标使用当前 capture viewport 的 CSS 像素；源像素样式和截图几何转换继续沿用既有契约。
- 保留现有属性编辑事务、连续绘制、选中对象、撤销重做、IME、输出及 OCR 边界。

**Non-Goals:**

- 不提供属性面板独立拖动、跨会话位置偏好、多屏自由拖窗或新增标注工具。
- 不改变 Rust/TS IPC、截图媒体、导出 lease、数据存储版本或操作系统支持矩阵。

## Decisions

### 1. 使用插件内布局模型，分别输出工具栏与属性面板位置

扩展现有纯几何模型，以主工具栏实际宽高、选区、视口、稳定属性预留高度为输入；依次评估外下、外上、内下，再做视口兜底。工具栏本身居中，不以“工具栏加属性面板”的联合宽度居中。保留当前 8px 安全边距、选区间隔和内部 inset。

属性面板独立计算水平坐标：自动和手动模式均关联具体工具按钮、跟随横向滚动并钳制到视口；面板比主工具栏宽时也不改变主工具栏中心。外下结构为“选区 / 工具栏 / 属性”；外上为“属性 / 工具栏 / 选区”；内下为选区内部的“属性 / 工具栏”。属性区域高度不渲染为空白占位。

尺寸/圆角条只由选区、视口和自身尺寸决定位置：优先放在选区左上方，垂直间距 2px；没有上方空间则贴在选区内部顶部下方 2px。工具栏位置不参与计算；用户手动移动工具栏时允许覆盖尺寸条，尺寸条不避让、不漂移。仅视口物理边界需要兜底钳制。尺寸条向宿主单向报告自身矩形；自动工具栏向上或向下放置时，先避开固定尺寸条再检查完整空间是否足够。手动工具栏忽略这项自动避让，因此可以主动遮挡尺寸条。

替代方案：继续测量整个活动 stack 实现简单，但会让面板开关影响布局；通用浮层库擅长单浮层翻转，却仍需要自定义三档优先级、稳定预留和尺寸条协调，当前无需引入新依赖。

### 2. 响应式最大高度提前测量，按视口与语言更新

在 capture 初始化时以当前可用宽度测量各工具面板的最大高度，包含当前布局支持的默认/选中对象上下文。测量节点必须不可交互、不可访问、无副作用，不进入截图内容，不产生重复可聚焦控件或冲突 ID；测量结果未就绪前沿用现有 ready 门禁，不能先展示错误位置再跳动。

视口、语言或有效布局宽度变化后重新测量；工具切换、输入值变化、面板隐藏及工具栏手动移动不能把预留收缩到当前面板高度。观察器和测量节点按会话清理，避免在每个 pointermove 中重新测量全部面板。极矮视口对属性内容设置可用高度上限并内部滚动。

替代方案：硬编码约 98px 仅适用于历史桌面矩形样例，不能覆盖语言、指针尺寸和滚动条差异；按当前面板测量又会恢复原来的跳位。

### 3. 工具栏拥有唯一的会话内手动位置

2026-10-24 维护者澄清：主工具栏可拖动，标注属性面板必须随工具栏移动，不能单独拖动。该明确要求替代此前的独立面板拖动设计。

专用 Hook 使用自动/手动联合类型管理工具栏的视口坐标，手动状态同时保留开始移动时的属性展开方向。属性面板坐标只从工具栏、当前按钮锚点及自身尺寸推导，没有独立手动状态。拖动过程中保持原来的上下关系；工具/对象切换、隐藏重开及选区变化保留工具栏手动位置，只有越界时做最小平移。横向边缘继续钳制属性面板并保持 caret 关联。

拖动钳制包含工具栏和当前响应式最大属性预留高度，极矮视口先约束属性内部滚动。使用 Pointer Events 与 pointer capture，正常释放提交，pointercancel、异常失去捕获或 Escape 恢复整组原位置和原模式。手势只更新会话 UI 状态，不进入标注 reducer、样式存储、裁剪、历史、导出或 IPC。新截图恢复自动布局；卸载释放捕获与监听器。

### 4. 工具栏提供拖动与位置恢复，属性面板只编辑标注

主工具栏固定区域仅保留一个 28×40px 点阵手柄，不显示“拖动”文字，也没有单独复原按钮。双击点阵恢复整组自动位置；键盘 Enter/Space 提供相同功能。完整中英文 accessible name/tooltip 说明拖动、双击复原与键盘操作。该手柄不随原有 15 个动作横向滚动而隐藏。

可聚焦手柄继续支持方向键 1px、Shift+方向键 10px，事件不触发画布热键。双击由无移动的两次指针释放后执行恢复，不创建拖动或编辑历史。位置恢复不改样式，样式重置不改变整组位置。属性面板没有独立拖动入口，手动模式仍保留 caret。


### 5. 紧凑工具栏与红色默认值采用局部变更

按钮 40px、图标 20px、组内 2px、组间及 padding 4px；调整分隔线外边距，避免叠加形成旧间距。保留功能顺序、禁用状态、焦点和横向滚动，键盘聚焦应将动作滚入可视区域。此前设计的 44px 约束在本轮桌面工具栏范围内由已确认的 40px 替代，不据此缩小其他产品界面或声明触屏体验通过。

仅将五个有颜色工具的工厂默认值改为现有 `#ff5252`。现有 normalize/read/reset 路径继续工作：首次或无效颜色 fallback 为红，有效旧绿色照常读取；重置当前工具使用新工厂值并保存。不迁移版本、不批量覆盖保存颜色、不重绘已有对象，选区绿色继续使用当前定义。

### 6. 统一两行属性编辑框

维护者要求所有工具统一两行，并将颜色收敛为 5 个常用色加自定义入口。第一行为工具与紧凑上下文、红/黄/绿/蓝/黑、自定义颜色、形状/箭头/粗体等现有选项及重置；第二行为所有数值参数。保留原有滑杆、数值输入、事务、验证、完整中英 accessible name 及 selected/default 区分，不删除功能。

沿用现有原生 `input type=color`，用调色盘图标明确入口，不引入颜色库。预设列表只影响呈现，任意合法已保存颜色继续有效；没有颜色的 Mosaic 不增加颜色设置。窄屏通过同一个内容容器横向滚动保持两行，键盘焦点自动显露控件。可见壳宽度与内容自然高度/滚动条厚度分开测量，所有工具及上下文采用同样测量结构，避免 reservation 与实际高度不同。

## Risks / Trade-offs

- [最大预留会让部分无需属性的操作更早转到上方] → 接受以换取稳定布局，不显示空白面板，针对无面板和最高面板记录相同选区下的位置证据。
- [测量与定位产生 ResizeObserver 循环或首帧闪动] → 分离实际控件和测量约束，仅提交变化的尺寸，保留 ready 门禁，浏览器检查无循环警告。
- [极小视口无法让所有控件完全无覆盖] → 主操作条保持可达，属性保持两行并内部滚动，显式记录兜底；手动模式允许主动覆盖。
- [拖动与滑块、文本、画布热键争夺事件] → 只允许手柄启动，明确指针捕获和 Escape 层级，回归鼠标、键盘、IME 与取消路径。
- [用户保存的绿色使升级后仍看到绿色标注] → 遵循已确认的兼容策略，重置工具默认值即可用红色，不擅自迁移。
- [浏览器 fixture 不等于原生 WebView 与屏幕体验] → 单独执行真实 macOS `pnpm tauri dev` 验证；保留混合 DPI、多屏、Windows 原有证据边界。

## Migration Plan

本变更按定位模型、工具栏整组拖动、样式/默认值及回归验证落地；无需数据迁移或 Rust 契约迁移。已有保存配置不在初始化时重写。回滚运行时代码不应删除用户偏好，新保存的红色作为合法自定义色继续兼容旧格式。

前置未归档变更的手动验收任务保持原状态。commit、push、发布、规范同步或归档均需维护者分别授权，不由实现完成自动触发。
