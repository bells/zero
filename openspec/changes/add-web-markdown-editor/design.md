## Context

需求与边界见 [proposal.md](proposal.md)。当前 `website/` 是独立 Astro 静态站，七个工具使用双语 content 清单、webTools 组件、浏览器 scripts 和纯 TS lib。`categories.ts` 仅接受 development/image；`web-tools.ts` 目前按 image 前缀推导分类，新增 Markdown 时须改为显式完整映射。

网站已经安装 CodeMirror 基础包和 JSON 语言包，没有浏览器 Markdown/PDF 生成库。现有 IBM Plex 字体资源只有 Latin，中文 UI 依赖系统字体；不能将其视为可嵌入中文 PDF 的字体。既有工具隐私文案是“不保存、不请求输入 URL”，本功能必须准确区分默认临时内容、用户主动保存草稿和主动加载图片。

本次仅规划。参考站和候选库文档已调研，未安装或运行 Markdown/PDF 候选，也未验证字体、分页或 Safari 下载。本文库名是候选方案，功能是否可交付取决于任务中的固定版本实验和验收。

## Goals / Non-Goals

**Goals:**

- 源文为唯一编辑事实源，共用一棵有位置信息的 Markdown 语法树，统一预览、目录和导出语义；UI、纯文档规则和浏览器适配可分别验证。
- 将 `.md`、独立 `.html`、文字型 `.pdf` 作为三种真实下载输出；PDF 直接生成文件，打印为另一个入口。
- 把不可信文档、可选持久化、主动网络请求和有界导出作业分别建模，默认不产生内容存储或外部图片请求。
- 重型编辑器、解析/高亮、PDF、中文字体均在所需交互后由本站按需加载；保持既有工具和产品页面的资源边界。

**Non-Goals:**

- 所见即所得、多文档库、协作、登录、云同步、AI、远程网页提取、PDF/Word/Excel 转 Markdown、图片上传服务。
- 公式、Mermaid 图表、多套发布主题、Word/图片导出、自定义字体上传、用户脚本/HTML/CSS 执行。
- 桌面插件、Tauri IPC、复用 Zero File 的隔离引擎、服务端生成或静默远程兜底。
- 首次离线打开、任意语言字形/emoji 全覆盖、与屏幕像素一致的 PDF、无限大文档或所有移动浏览器的下载保证。

## Decisions

### 1. 在现有官网内增加独立工作区和显式分类

新增 `text` 分类，中文「文本类」、英文「Text」，仅包含本次 `markdown`；diff 继续在开发类。注册表、分类解析器、分类 URL 白名单、目录内搜索、全工具搜索、语言导航和静态内链同步更新，显示八个实际工具，不显示空的未来类别。沿用 `/tools/{slug}/` 双语路由和站点 base。

拟增加 `components/webTools/MarkdownWorkspace.astro` 和 `scripts/web-tools/markdown-workspace.ts`，共享工具 shell 仅做注册与路由接线。纯 TS 文档、策略、文件名和导出模型放在 `lib/web-tools/markdown-*`；文件读取、草稿存储、Worker、字体/图片获取、Blob 下载和打印属于 browser adapters。没有 Rust 侧或跨端契约。

替代方案：直接归开发类偏离已确认分类；迁移 diff 扩大现有变更；把编辑器放进桌面 React 或 File 引擎会破坏独立站点交付边界。

### 2. 共用语义模型，增强编辑失败仍可输入

复用 CodeMirror 6 基础包并评估其 Markdown 扩展；基础 textarea 在增强加载失败时仍支持粘贴、文本编辑和源文下载。优先评估 unified/remark-parse/remark-gfm 的带源位置 AST，以单一受控管线产生预览、标题目录和 PDF 文档模型；预览路径评估 remark-rehype、rehype-sanitize 和受限高亮器，保持禁止原始 HTML执行。具体插件版本、schema 与实际分发许可在原型中锁定。

不自行编写 Markdown 解析器、通用编辑器或 PDF 排版引擎。代码高亮采用有界语言集合并保留未知语言的纯文本回退；禁用插件的运行时远程下载。`mermaid` 等未支持围栏按普通代码呈现，数学文本不触发外部渲染。

源文修改递增 `documentRevision`，防抖后向可终止 Worker 请求解析/清洗/高亮，响应含 requestId/revision 和判别联合结果；未知消息经 `unknown` 收窄，禁止 TS `any`。迟到结果不替换新文档。导出固定不可变文档快照，输入、导入或清空变化使旧导出失效；只有对应当前 revision 的成功结果可下载。

替代方案：预览和 PDF 分别再次解析容易出现语法分叉；一个通用 `innerHTML` 路径无法约束恶意输入；把完整编辑器随首屏加载会破坏既有预算。

### 3. 模式和辅助操作保持源文语义

源码/预览/分屏显式可切换；以 800 CSS px 为初始窄屏断点，窄屏默认源码，桌面默认分屏，具体断点通过响应式验收调整而不改变模式语义。手动选择不因每次窗口变化被无提示重置；窄屏不强制左右并排。使用官网主题和工作区扩展布局，支持全屏；Fullscreen API 不可用时提供可退出的页面内扩展模式，Escape 和关闭动作恢复焦点。

工具栏插入或包裹源文，遵循选区并可撤销；查找替换、缩进、列表续写等复用编辑器能力。快捷键限定在编辑区，尊重 IME composition，不能劫持官网 Cmd/Ctrl+K 全工具搜索。目录来自 AST 标题及稳定唯一锚点；滚动同步按源位置和渲染块映射，用户可关闭，以重入保护避免双向跳动。字符统计使用 Unicode 码点，字词统计使用可用的分词能力并明确计数口径，不将解析 HTML 字符数当源文字数。

替代方案：手机始终分屏难以输入；简单全页比例同步对代码/表格/图片错位明显；自己实现通用编辑器查找会重复既有能力。

### 4. 严格文本导入及主动草稿例外

只读单个 `.md` / `.markdown` / `.txt`，使用严格 UTF-8，接受并去除开头 BOM，规范 CRLF/CR 为 LF，不猜 GBK，也不尝试从扩展名推断 Office/PDF 内容。粘贴、导入和草稿恢复共用输入策略；失败保留当前文档。覆盖已有编辑或主动清空前提供可取消的确认，取消不丢失源文。

草稿默认关闭，开关文字明确说明“在此浏览器保存草稿”。按站点 origin 的版本化专用键保留一份文档，两个语言页面共用；仅在开启后防抖保存源文及必要状态，不保存图片字节、授权、历史、多版本、搜索词或导出文件。关闭开关停止后续写入并删除已保存草稿，同时保留当前内存源文；另有明确“删除本地草稿”操作，删除必须同时取消待写入任务，避免重建已删除数据。自动保存被主动开启时，普通编辑清空可保存为空文档，但不能与“删除本地草稿”混淆。

恢复前校验 schema/字节/行数，恢复内容仍走不可信文档管线；图片授权不随恢复生效。存储禁用、配额失败或损坏时显示未保存状态，编辑和下载继续可用，不宣称已保存，也不清理其他工具数据。页面卸载尽力清理资源，不承诺浏览器崩溃或系统强杀时可保证保存。

替代方案：默认自动保存违背已确认隐私；只加存储调用而不改公共文案会产生误导；通过语言 URL/片段传输正文会泄露内容。

### 5. 不可信内容与授权图片使用受限资产适配器

原始 HTML 作为可见文字或安全忽略的源内容，预览与导出不解释其脚本、事件、iframe、内联样式或表单。Markdown 文本、代码、链接、标题和文件名分别按上下文转义，清洗结果是唯一允许进入 DOM 的 HTML。拒绝 javascript 等活动协议，普通链接使用安全新页属性；任务列表预览不直接改变源文。

发现图片语法时先生成占位，不进行 DNS/HTTP 请求、预取、代理或字体/样式提取。用户在当前文档明确允许后，才按展示的 HTTP(S) 图片来源加载；后续编辑新增来源重新授权，导入/恢复/离页撤销授权。优先用 `credentials: omit`、no-referrer 的 CORS fetch 获取有界字节，再校验实际 MIME/签名和解码尺寸，通过 Blob URL 预览并在导出中复用。只接收受支持的静态 PNG/JPEG/WebP；SVG、活动资源、动画、过大/超时/CORS 拒绝显示原因。跳转不能绕过已授权来源；无法安全验证的跳转失败并提示。

图片只能在授权后发出其 URL 所表达的请求；文档正文、文件名、草稿和导出参数绝不附加到 URL、日志、遥测或反馈。这是局部图片例外，不授予任意链接抓取、上传或服务器代理权限。

未能嵌入的图片在导出前列明原因，由用户明确选择保留占位继续，或者返回修正/取消；不静默丢图。下载 HTML 不保留会自动访问第三方的图片/字体/CSS URL，成功获取且适合嵌入的图片作为本地数据嵌入，其余保留安全占位。普通文本链接可保留，点击是独立用户动作。

替代方案：直接把所有 `<img src>` 放入预览会在授权前请求；允许显示不等于浏览器允许读取字节用于 PDF；服务端代理突破本地边界。为了明确的网络权限和两种导出一致性，接受部分无 CORS 图片不可嵌入的限制并展示出来。

### 6. 三种真实文件输出，PDF 使用语义排版

统一按当前快照的文档标题/导入 basename 派生安全文件名，移除路径、控制字符及非法后缀，空名回退 `document`；MIME 与实际扩展名一致。不输出本地路径、草稿开关、来源 URL 等非正文信息。

- `.md`：UTF-8 当前源文（按导入规则处理后的文本），不包含演示内容或陈旧快照；复制操作遵循同一源文，剪贴板失败提供手动复制。
- `.html`：完整 UTF-8 文档（doctype、lang、title、正文、内嵌 CSS），只含受控正文和经授权已本地获取的资产，不包含编辑器/统计/工具栏。无执行脚本、第三方资源和站点依赖，加入限制脚本/连接/嵌入内容的 CSP；正常表格、代码高亮、链接和文档锚点可用。
- `.pdf`：优先采用 pdfmake 的语义文档定义，AST 映射为文字、段落、列表、表格和代码片段；A4 纵向、浅色正文、自动分页。保留文字与链接，不能以整页截图替代可选择/搜索文字。跨页表格重复表头，标题避免孤立于页尾；长代码块可跨页，超宽行按专用导出排版换行且不截字，表格不能通过横向裁切漏列。页码作为文档辅助，不引入站点导航或浏览器 URL/时间页眉。

pdfmake 官方文档支持[客户端直接下载](https://pdfmake.github.io/docs/0.3/getting-started/client-side/methods/)、[自定义字体](https://pdfmake.github.io/docs/0.3/fonts/custom-fonts-client-side/)和[跨页表格表头](https://pdfmake.github.io/docs/0.3/document-definition-object/tables/)，但这些并不是 Zero 的集成证据。另配许可允许嵌入的中文字体，优先评估 OFL 字体及可复现子集化；源字体与构建/子集材料随实际分发核查。字体仅从本站按需获取，禁止把文档字符或正文发送到字体服务；字体缺失应失败，不能悄悄导出乱码。常见中文/拉丁字符覆盖和文本提取必须实测；对不支持字符明确反馈。

打印提供单独按钮和 `@media print` 正文排版，可使用浏览器另存 PDF，但不能作为“下载 PDF”的隐藏替代。html2pdf.js 的[已知限制](https://github.com/eKoopmans/html2pdf.js#known-issues)包括截图文字不可搜索/选择及 canvas 尺寸限制，因此不作为默认方案。服务端 Chromium 对排版更接近网页，但不符合本次纯浏览器处理边界。

### 7. 有界异步作业与资源生命周期

解析和 PDF 导出使用可终止的专属 Worker；请求/响应显式携带 documentRevision、jobId、阶段和稳定错误码。状态为 idle/loading/parsing/layout/encoding/success/error/cancelled，UI 持续可编辑、取消及导航。初次下载依赖/字体和实际生成分阶段显示；下载超时、生成超时与取消均保留源文。清空、导入、离页、revision 变化终止失效任务，并释放 Worker、图片引用和 Blob URL。浏览器内存崩溃无法以 try/catch 保证恢复，必须前置限额。

实施实验的初始候选策略如下；是待测的保守起点，不能当作已获实机认证的容量。最终数值实施时集中固化、页面公开并做边界测试，调整应记录原因，不改其他工具的旧策略。

| 项目 | 初始候选上限 |
| --- | --- |
| 源文/导入/草稿 | 1 MiB UTF-8、20,000 行 |
| 解析/高亮 | 每次 5 秒，可取消/终止 |
| 图片 | 最多 10 张；单张 5 MiB、1,600 万像素；合计源字节 20 MiB、解码像素 2,000 万 |
| 图片/字体请求 | 单请求 15 秒；中文源字体最多 32 MiB |
| HTML 输出 | 32 MiB（含已嵌入图片），构建前和过程中检查 |
| PDF 输出 | 32 MiB、500 页、生成 60 秒 |

输入太大时保留源文可复制/下载的退路，不让粘贴、导入、草稿恢复绕过限制进入昂贵解析。超页/超字节/加载失败不产生假成功或偷偷切成另一格式。取消后迟到数据不触发下载。

首屏保持自动执行 JS gzip ≤50 KiB、首屏资源 ≤1 MiB；PDF、中文字体、编辑器增强及高亮语言集合不得因预加载提前进入该预算。首次输入/点击增强后加载语义管线，PDF 按钮后加载 PDF/font，分别记录交互后体积和耗时。字体和 PDF Worker 的 CSP/base 兼容在原型阶段验证，不能拖到上线时再发现只能转服务端。

### 8. 发现、公共隐私说明与反馈保持同源事实

目录、工具导航和 SEO 标题从「开发与图片」调整为覆盖新增文本能力；新增两页，预期 36 个可索引页面/38 个 HTML，按实际路由集核对。中文/英文 canonical、hreflang、sitemap、WebApplication、llms 和浏览器 Agent 指南描述真实控件、导入格式、三种下载、图片授权和草稿开关，不宣称远程转换 API。目录的通用隐私摘要改为“默认本地处理；Markdown 可主动开启本机草稿及外部图片”，各旧工具继续明确临时行为。

若接入既有反馈 UI，注册稳定 `tools/markdown` 线程（两种语言共享），只变更必要 allowlist。反馈仍默认关闭、点击后加载异源 iframe，仅传 thread/locale。正文、标题、文件名、选区、字数、图片 URL、草稿、搜索、导出状态和错误原文均不得附送；反馈失败不影响编辑/下载。

## Risks / Trade-offs

- [中文 PDF 字体体积、缺字或复制乱码] → 自托管懒加载可嵌入字体；原型验证子集、许可、提取和字体缺失错误；不以截图掩盖文字失败。
- [PDF 与 HTML 排版不是同一引擎] → 共用 AST 和导出语义；分别验证中英混排、代码、跨页表格与链接，不承诺像素一致。
- [宽表/长代码/病理输入导致长时间布局] → 有界策略、Worker 终止、边界语料、明确溢出策略和可恢复错误。
- [主动草稿/图片与旧隐私文案冲突] → Markdown 局部例外、默认关闭/占位、逐页和共享摘要同步；网络/存储合成内容审计。
- [图片可见但 CORS 禁止读取] → 本地安全资产适配器、明确失败、用户选择占位继续，禁止服务器代理或静默丢图。
- [中英文页面恢复同一草稿或多标签覆盖] → 单篇版本化 schema、保存状态和恢复前校验；检测其他标签更新并提示冲突，不能默默覆盖较新草稿。
- [手机 Safari 下载/字体/PDF 峰值差异] → 分别记录 Chrome 自动化、桌面 Safari 与真实 iPhone 的下载打开/长文/内存/取消证据；仿真不能勾选实机任务。
- [多个未归档网站 delta 存在旧数量/类别和隐私绝对表述] → 本次只扩展 Markdown 的范围；实现保持全站文案一致，未来同步依赖顺序单独处理，不修改历史完成勾选。

## Migration Plan

1. 先固定并实验验证解析器/PDF/中文字体/Worker/许可和代表性文档，确认直接文字型 PDF 可行，记录字体成本与容量；若失败报告阻塞，不用打印或服务端冒充已交付。
2. 新增工作区、输入/语义管线、隐私与草稿、导出；按功能逐步接线分类/路由/搜索/指南/反馈。旧工具计算和原分类不迁移。
3. 串行执行 website check/test/build/test:seo/test:browser 与 links/performance 检查，补真实 Safari/iPhone 证据；未做实机验收的任务继续未勾选。
4. 维护指南和 overview 只在后续实现时更新为实际状态。提交、推送、部署、主规范同步与归档需独立授权。回滚可移除 Markdown 注册/路由/索引和专属资源，保留其他七工具；不静默删除用户主动保留的本地草稿或既有反馈数据。

## Open Questions

产品范围已确认。可在既定方案内由实施原型确定的是依赖精确版本、字体来源/可复现子集、支持字形范围、最终资源上限及经实测的浏览器版本；均有前置任务和记录要求。若实验只能提供截图 PDF、打印对话框或服务端转换，则超出已确认交付标准，须报告而不能自行降级。
