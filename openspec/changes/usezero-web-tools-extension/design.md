## Context

动机见 `proposal.md`。官网是 `website/` 独立 Astro 7 静态站，有双语 Layout、原生脚本、静态文档注册表、SEO/AI 索引及独立锁文件；没有 React/Tailwind。`[...page].astro` 与英文对应文件已生成五个 `/tools/<desktop-tool>/` 说明页。`Layout.astro` 当前把页面 about 关联到桌面 SoftwareApplication；新在线工具不能沿用这一归属暗示桌面已有相同功能。

`add-zero-product-website` 的基础能力尚未同步主规范；本变更保留其路由、预览隔离和下载事实。当前源码发行清单为 `unavailable`、空 packages，不能从这个状态生成“免费下载”直链。`package-zero-trial-profiles` 不为在线工具提供桌面交付承诺。

用户在 2026-10-14 确认后续希望以桌面插件提供离线使用。本轮保持官网范围，纯 TS domain 与 UI/worker 解耦以便未来复用；不新增当前桌面交付承诺。

## Goals / Non-Goals

**Goals:**
- 静态 HTML 提供完整说明与导航，浏览器增强承担计算；域逻辑与 UI/worker 解耦，全部采用严格 TS 和显式结果/错误类型。
- 以可验证的输入语义、资源上限和数据保真建立信任；沿用网站隔离和现有性能预算。
- 将新在线工具与既有桌面说明、桌面应用实体和下载事实清楚关联而不混同。

**Non-Goals:**
- 不新增桌面插件或 Rust/TS IPC，不做整站视觉重构、服务端转换、云历史、账号、批量文件处理或任意图片格式转换。
- 不做完整离线安装/PWA，不引入分析 SDK 或 A/B 平台；上线后的流量/转化验证另行定义。

## Decisions

### 1. 在现有站内新增双语工具区，保留已公开路径

使用静态 `/tools/index.astro` 与 `/tools/[tool].astro` 及英文对应入口，只生成三个在线 slug。Astro 静态与动态路由优先级、catch-all 的产物唯一性必须在构建与 URL 回归中验证；既有文档仍由原注册表生成，不移动已有 URL。在线注册表与桌面文档分开，统一校验 slug 不冲突。全部链接通过既有 `path`/base helper 生成。

目录突出三个可运行工具，下方以独立文字链接区列出“桌面工具说明”；导航把原首页工具锚点标为“桌面工具”，新增“在线工具”，两个入口同时保留。工具页上方工具切换/搜索，中部工作区，下方静态说明与桌面 CTA，手机纵向堆叠，不继承桌面 app 的壳层。

备选 `/web-tools/` 可避免语义交叠，但与用户给出的入口和现有工具 URL 体系不一致；迁移旧文档会带来无必要的 SEO 风险。

### 2. Astro + 原生 TypeScript；重能力由用户操作触发加载

建议模块为 `content/web-tools.ts`（双语 metadata/说明/示例）、`components/webTools/`、`scripts/web-tools/` 和 `lib/web-tools/`（纯转换逻辑与 worker 契约），工具样式独立作用域。搜索与工具自身脚本只出现在工具区，不向首页/下载/桌面说明注入编辑器。

JSON 首屏提供有标签的 textarea；显式启用“增强编辑”后动态加载 CodeMirror 6 的 JSON 语言、折叠和错误标记，保持输入、选区及可访问降级。解析/格式化优先采用严格模式的 `jsonc-parser`（禁注释/尾逗号），利用 token/编辑信息保留数字词法与重复键，不经 `JSON.parse`→`JSON.stringify` 重写用户文档；解转义仅解析顶层 JSON string 一次，再校验其内容。实施前核对候选包官方文档、维护状态、许可证、浏览器/worker 兼容和实际打包体积，锁定经验证版本；无法满足保真契约则换兼容库。

Monaco、全站 React hydration 和新 CSS 框架会扩大独立站依赖与首屏成本，目前不采用。时区和 UTF-8 使用原生 Date/Intl/TextEncoder/TextDecoder；领域特有的规则直接实现和测试，不为它们引入通用大包。

### 3. 本地计算、显式执行和有界异步任务

时间输入可做短延迟自动转换；JSON/编码按显式按钮执行，避免每次按键处理大内容。JSON 和较大文本/图片字节任务在站内 worker 执行，使用 `{requestId, operation, input}` 与 discriminated union 结果；输入变化、清空、切页或再次执行使旧 request 失效。任务超过 5 秒终止 worker 并报告可重试错误；不接受晚到结果。loading 时可取消，取消销毁当前 worker，后续任务创建新实例。

时间输入上限 256 字符；JSON 与文本编码原始输入最多 1 MiB UTF-8，输出最多 8 MiB；JSON 嵌套最多 128 层。图片原始/解码字节最多 5 MiB，Data URL/Base64 输入最多 7 MiB，尺寸最多 16 million pixels。读取前检查文件大小，解码前预估字节大小；worker 内用成熟可在浏览器运行的头部元数据解析库核验 PNG/JPEG/WebP 的真实 MIME 和尺寸，再交给浏览器图像解码。不得自行扩展复杂图片解析器。输出有界，展示可滚动/分块，不把多 MiB 一次塞入高亮 DOM。具体库选择及压力测量在任务中记录。

输入/结果/搜索词不进入 localStorage、IndexedDB、URL、日志或遥测；主题偏好是唯一持久化例外，仅存 system/light/dark，无权存储时回退 system。工具不发计算请求、不加载第三方脚本/字体/CDN，不抓取输入中的 URL。页面资源可同源下载；这不等于首次离线访问有保证。显式复制/下载之外不向外转移内容；清空和离开工具释放引用/Blob URL，不承诺 JavaScript 内存安全擦除，也不能控制浏览器/系统自身历史恢复机制。

### 4. 时间戳采用可解释且跨浏览器确定的规则

- 时钟显示 `floor(Date.now()/1000)` 与同一快照的毫秒；定时器仅触发采样，不累加秒数。暂停冻结显示和复制值，继续立即采样；页面隐藏暂停 tick，回来时按运行状态重新采样。
- 自动单位仅对绝对值十进制数字部分恰为 10/13 位的有符号整数推断秒/毫秒，其余整数（包括 `0`、负的小值、11/12 位）提示显式选秒/毫秒；提供 自动/秒/毫秒，显示实际采用的单位。拒绝小数、科学记数、超出安全整数或 Date 范围的数值。
- 接受带 `Z` 或 `±HH:mm` 的 ISO 日期时间，以及严格 `YYYY-MM-DD HH:mm:ss[.SSS]`（小数秒 1–3 位）的无偏移格式。无偏移输入默认“北京时间 UTC+08:00”，允许显式选择 UTC；始终显示这个解释。日期-only、斜杠日期、英文自然语言等返回支持格式提示，不交给宽松 Date.parse 猜测。
- 严格检查公历日期/闰年/时分秒和偏移，不归一化 2 月 30 日，不接受闰秒；显示北京时间（固定 UTC+08:00）、UTC、ISO 8601、秒/毫秒整数和双语相对时间。不用 Asia/Shanghai 历史规则隐式换算。秒结果向负无穷取整，保留毫秒结果。
- 相对时间与运行/暂停时钟使用同一参考快照；不每秒 aria-live 播报。其他时区/DST 选择器在首期外。

### 5. JSON 的默认行为是保留信息

支持全部严格 JSON 顶层值。格式化为两空格缩进，压缩只去除字符串外空白；两者保留键顺序、重复键、数字词法（包括超出 JS 安全整数的大数）。重复键可提示但不能悄然覆盖。错误带本地化原因与 1-based 行/列，CRLF/Unicode 定位纳入测试。无效输入保留原文并清除/标记旧结果不可复制。

“去除转义”只接受一个合法顶层 JSON string，其解码内容还须是合法 JSON 文档；成功后替换输入为解码的一层文档。普通 JSON 对象、裸 `\\` 序列或解码后非法文档返回说明，不做正则删除反斜杠，不递归重复解码，不执行代码。

### 6. 编码模式分离，图片处理不加载远程内容

文本 Base64 走 UTF-8 bytes，兼容中文/emoji；解码接受标准 alphabet、合法有/无 padding 和 ASCII 空白，其他字符/错误长度报错，Base64URL 不隐式混用。无法以严格 UTF-8 解码的 bytes 提示改用图片模式，不输出替代字符冒充成功。

URL 操作明确命名为“URL 组件编码/解码”，对应 encodeURIComponent/decodeURIComponent，不把整条 URL 当可访问地址，不把 `+` 当空格（form-urlencoded 首期外），错误 percent/UTF-8 保留原文报错。

图片模式支持本地文件→Data URL/纯 Base64、相同受支持字节的 Data URL/纯 Base64→预览及显式下载，不重新压缩或变更图片格式。核对声明 MIME、签名与尺寸；SVG/HTML、远程 URL、损坏内容拒绝处理。使用 Blob URL 作为预览源、固定安全下载扩展名，不使用用户输入拼 HTML；替换/清空/离页撤销 URL。图片和文本模式的限额分别说明。

### 7. 工具区主题、搜索和反馈复用网站语言

保留现有字体、Ø、冷青强调及简洁内容层级，通过工具区 token 提供浅/深/system，深色需覆盖同页 header/footer 保持完整；既有产品页继续原样式。浅深都验收 AA、focus、200% 缩放、320px 与触摸 44px。

工具区提供可见搜索按钮和原生 dialog；Cmd/Ctrl+K 在工具区打开/关闭本地三个工具的搜索，输入法合成期间不拦截，其他页面保留浏览器快捷键。支持 Arrow/Enter、Escape、焦点约束与关闭后返回触发点；空结果有文本。普通链接和目录无 JS 可达。复制仅来自主动点击，Clipboard API 失败则提供可选文本和手动复制提示，不虚报成功；成功/失败使用适度 aria-live，不抢焦点。

### 8. 发现与导流必须表述在线能力和桌面能力的真实关系

每页预渲染唯一 H1/title/description、输入语义、示例、隐私/限额和简短 FAQ，中文/英文路由互相对应，sitemap 与 llms 索引同源于注册表。扩展 SEO 模型让各工具页 about 指向独立 WebApplication（Browser/JavaScript），目录使用 CollectionPage/ItemList 关联这些工具，不将在线功能写进桌面软件 featureList；不增加虚构 rating/offer。preview/noindex/404/base 行为沿用现有站。

CTA 示例：“还需要桌面上的效率工具？了解 Zero 的截图、保持唤醒、壁纸与应用启动。”按钮复用下载目录的状态，当前为“查看试用方式/了解 Zero”。旁边说明这些在线工具暂未内置桌面版；如提 Launch 快捷键，macOS 是 Option+Space，Windows 是 Ctrl+Alt+Space，只对应已支持的应用启动能力，首期 CTA 可直接不提快捷键。无包不生成平台下载直链。

### 9. 验证采用网站独立门禁

补纯函数/worker 合成 fixture：时间单位/负值/闰年/非法输入、JSON CRLF 定位/大数/重复键/解转义、Unicode/非法编码、图片 MIME/限额/尺寸、取消/timeout/晚到结果。浏览器覆盖两语言、旧文档不变、主题、搜索、复制拒绝、无 JS、worker 失败、清空、输入不出网/不落站点存储、脚本式内容安全显示和图片 URL 释放。

扩展现有 `check/test/build/test:seo/test:browser/verify:performance`，避免只测旧的 18 页硬编码集合。生产可索引 HTML 预期增加 8 页至 26 页。目录和三个工具均测初始 JS gzip ≤50 KiB、首屏静态资源 ≤1 MiB，固定 Lighthouse mobile performance/accessibility ≥95、LCP ≤2.5s、CLS ≤0.1；统计初始所有实际加载脚本/worker，不用 chunk 命名规避预算。增强编辑器加载前后分别记录体积/初始化和大输入交互，启用编辑器时保持取消和输入可用。网站全套检查不运行桌面 prebuild，桌面构建仅在怀疑隔离边界被触及时检查，不为纯官网改动扩展 Rust/设备验收。

## Risks / Trade-offs

- [同 `/tools/` 下混合在线功能和桌面说明] → 导航/目录明确标识，保留旧 URL，回归构建重复路由和搜索落地。
- [编辑器超预算/增强失败] → 延迟到用户交互加载、保留 textarea、按实际请求测量，必要时更换轻量实现。
- [大输入与压缩图片消耗内存] → 读入前及解码前限额、头部尺寸验证、worker 终止/取消；压力测试不能替代所有设备保证。
- [时间猜测造成错误业务判断] → 限定自动推断、严格日期、明确固定 UTC+8 与 UTC，无歧义兜底。
- [本地处理被宣传成绝对安全或完全离线] → 文案只承诺本站工具不传输/持久化正文；静态加载与浏览器自身行为另行解释。
- [为获流量堆薄内容或误导下载] → 每页提供实际可运行能力与语义说明；下载依清单，SEO/转化保留上线验证边界。

## Migration Plan

1. 在 `website/` 增量加入注册表、页面和独立依赖，保持旧路由/清单不变，更新维护地图与独立 CI。
2. 完成自动及浏览器/性能验收，交付本地静态预览与可复现记录；不改基础变更的历史 evidence。
3. 若后续获部署授权，核对生产发行目录、preview/production 索引、旧/新工具 HTTP 路由和 CSP/worker 兼容后发布整份静态产物；搜索平台提交另行授权。
4. 回退时恢复上一完整网站产物与锁文件即可；不存在用户数据迁移。spec sync/归档前先协调 `add-zero-product-website` 的基础规范。
